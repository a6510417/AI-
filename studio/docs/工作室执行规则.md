# 工作室执行规则

这份文件集中保存九个项目入口共同使用的规则。创作方法仍在技能库，空白交付骨架仍在模板库，机器字段与命令仍由[数据协议](数据协议.md)和[接口规范](接口规范.md)定义。各文件只维护自己的职责；项目布局与资产生命周期见[重构实施说明](重构实施说明.md)。

## 一、本轮目标与最小路线

先确认用户要的是分析、图片方案、实际生图、即梦提示词、媒体验收、后期交接还是发布任务，沿用已明确的权限与停止点。普通设计与可逆整理在授权范围内继续完成；关键剧情、人物身份、世界规则或硬约束存在无法消除的矛盾时，只暂停依赖该矛盾的部分。

九个标准入口位于工作区 `.agents/skills/`，由任务语义选择。前四项按需读取现有00—19手册，后五项读取20—24工作室手册。不要求单图、单镜或单次审查先跑完整IP流程；看到目录或链接不算已读取正文。纯假设演练、规划或操作单没有实际项目或媒体时，用给定材料交付文字并列缺项，不为执行流程制造项目、采用基准或媒体登记。

题材模板、五拍、播报节奏和内容取向是选用方案或写法建议，只有本项目明确选用或用户定为硬目标时才约束本项目。单个题材元素不自动引入其他世界机制；偏离推荐写法不等于事实或连续性错误。阶段交接按本轮目标执行，未授权阶段只列下一输入，不因手册写“交下一阶段”自动制作或新增报告。

本轮判断须分清共同规则强制项、已选写法建议和执行者自行选择。原稿完整存档不要求观众在开场听完背景、属性和奖励；按06选择此刻必需信息，来源仍可追溯。已获改编权时，合理动作衔接、视听表达和技能特效可在权限内设计；是否改变能力功能、动机、关系或胜负须分别核对，不能把制作补全一律当成越界。

合理改编也可修复原作薄弱或不合理的局部事件：事故如何触发、人物如何行动、场面怎样升级和转场，均可在已获权限内重写。保护关键因果是保护决定胜负、关系、核心动机及能力功能／时点的条件和本版内部自洽，不是冻结原作每个动作与触发细节。必要前史若能建立人物性格、反差、情绪或展示制作目标，应写成有效场面；不能把压缩原则执行成一律删掉前史、奇观和风格化表达。明确的忠实整理任务才按其禁止补写范围处理。

## 二、读取真实采用基准

小说转短剧默认围绕60～120秒的手机观看设计；用户明确其它形态时采用其目标。改编先形成角色行动、冲突变化和视觉表达，再整理正式字段，不能用表格完整代替场面有效。具体权限分类、视觉机会识别和导演决策见[06改编](../技能库/06_剧情改编技能.md)，不把推荐节奏固化成每集相同的段落比例。

阶段依赖原文或纠错正文时，在制作上下文中声明实际必读范围，核对 `reading_requirements`；只选摘要不能证明必要原文已经进入上下文。固定视觉使用已选精确资产版本，服装、饰物与武器按职责引用，镜头不重新设计已锁组件。执行字段由[数据协议](数据协议.md)维护；声明锁定、登记采用和实际媒体一致性分别判断。

1. 找到工作区根的 `projects/IP编号_项目名/` 与 `project.json`。有多个候选时，根据用户明确项目和素材来源判断，仍无法判断才澄清归属，不混用故事。
2. 续做、审核、采用或交接前调用已有 `status --json`。从工作区根运行时，工具路径是 `studio/bin/studio.mjs`。状态命令只读；报错或未完成事务先按既有部署说明处理，不能把失败结果当成功。
3. 读取当前采用版本在 `.ip-system/snapshots/<资产ID>/<版本>/` 的 `asset.json` 及本轮需要的正文、附件或媒体。实际快照以登记路径为准，不从修改时间、工作稿文件名或所谓“最新图”猜选。
4. `status` 的 `title` 来自工作稿，仅用于定位。故事设定、视觉要求、具体文件和用途以采用快照内容为准；未保存工作稿和候选另列。续作包与当前状态不同，说明差异并按本轮目标选取真实版本。

小任务只读必要来源与直接受影响依赖。引用ID、版本和必要事件节点，保留旧版的取舍按已有复核方式记录，不默改历史。

采用指针只回答当前登记使用哪个版本，不证明创作质量合格。用户已明确否定该版时，保留原采用和审核历史，把本轮质量结论、修订候选与登记基准分开；不能用“已采用”或旧通过记录推翻用户的质量目标。工作区项目存在性以实际目录与project.json为准，命令占位、临时测试项目及失效历史记录不能写成现行项目事实。

### 纠错汇入与当前基准

续做与交接同时核对当前采用快照和直接相关的纠错、未解决记录。在已授权的项目修订范围内，更正须实际汇入受影响资产的新版本，回查相关正文和相邻因果，登记精确快照审核并按已有授权采用；完成对应复查与采用后才关闭“当前基准已纠正”的问题。既有 REPORT 用准确引用组织“旧值 → 正确值 → 出处 → 影响范围与处理状态”，不只在末尾附提醒，也不复制另一套事实源。尚未汇入、审核或采用的更正明确为候选／待完成，不能假称当前基准已经更新。原稿、旧快照和旧审核保留；维护共享技能与规则不包含修改项目资产的授权。

### 小说接入与文件职责

原稿保持原始字节；用户要求无损分章时保留包装片段、顺序和重建核验，不清洗存档。只有进入本轮制作的章节才建立必要正式CH来源包，其余章节只保留来源定位。接入使用[接口规范](接口规范.md)中的通用工具，不为每本书复制专用执行脚本。

索引只维护章节定位与异常引用，拼接只维护分段顺序，异常详情只有一处权威记录；中文摘要按该记录派生，不人工维护另一份同义详情。HTML、广告和错号保留在原稿；仅按实际选章、显式清理项生成带原稿哈希、位置和变换记录的制作阅读文本，不另造全书清理副本。疑似广告不凭关键词自动删除剧情。

用户授权长篇或完整范围分析时，按[01小说分析](../技能库/01_小说分析技能.md)完成批内提取、跨批归并和篇章因果综合，分别报告实际阅读、信息提取、综合结论及生产可用范围；拥有原稿、扫描完成或已读覆盖完整不代替后三项。局部取材不自动扩展为全书分析，只为本轮必要制作章节建立 CH。

## 三、视觉基准与参考职责

沿用[04角色一致性管理](../技能库/04_角色一致性管理技能.md)维护身份、画风、服装、固定饰物与时点变体。采用图中的设计取舍不自动成为小说事实；设计版本、故事状态与图片版本分别定位。换视觉基准先核对直接受影响的图与镜头，不把所有旧成果自动判废。

每个输入文件写清负责身份、服装、画风、构图、动作起态、首尾帧或编辑目标中的哪一项，以及哪些内容不得借用。人物纯底定妆图不承担剧情空间；场景首帧不保证未显示的角色细节。未知、遮挡、未查看部位保留限制说明。

用户描述的候选未定位到确切文件时，不擅自与登记MEDIA合并。同一文件的实际观察与冻结说明冲突时分别记录来源，暂缓受冲突影响的用途并核对真实媒体；已采用状态不能覆盖实际观测。

图像编辑同时检查修改处与保留项，使用当前可调用的生图工具，不套用未暴露的API种子、蒙版、权重或型号。即梦按实际版本、入口、模式与界面引用名称组织视频稿；发布资料、账号可用组合和真实结果分别记录。负面词按入口实际支持情况使用，不能保证文本里的排除句必然执行。

### 小说到图片的依据核对

用户要求按小说制作时，先区分忠实复原与授权改编：前者严格核对本轮选用正文及事件；后者以本轮明确选用的改编路线为本用途依据，核对与原文的差异、权限及影响，不能自动退回被用户否定的旧稿。小说未描述的外观可在授权范围内合理补全并标明来源；已授权的剧情与视觉改编保留差异与适用范围。候选可按本轮授权创作，保存、正式审核和采用仍分别执行，不因此改写历史。按[19视觉基准与图片交付模板](../模板库/19_视觉基准与图片交付模板.md)中的“本图可见要求与来源对应”核对实际来源、当前状态、最终提示词和实际图片，单图只列与本用途有关的要求。

1. **回查相关正文**：角色卡、摘要、出场清单及旧提示词用于定位。正文可读时，读取角色相关描写、目标事件和必要前后文，核对实际出场者、持物及关键动作；区分当前事件、回忆、传闻、人物想象和未发生的原书计划。只有摘要时注明“上游标注，未回查原文”及影响，不把该限制变成忠实度通过，也不要求重跑全书分析。
2. **筛选本图状态**：从跨章角色／场景汇总中选出本图时点生效的服装、伤势、道具、能力显现、空间与毁损状态，不能直接复制其中的通用 `image_prompt`。身份和剧情依据、当前采用的视觉设计、旧参考建议分别核对；旧建议与本用途采用设计不同，写清未继承项，不能自动恢复。
3. **逐项区分事实与补全**：普通脸型、发型、面料纹理和裁剪可合理设计。阵营／等级标记、婚恋饰物、伤势、法器归属、能力觉醒及身份揭晓会改变剧情含义，按剧情设定或明确授权处理，不能仅归为美术补全。资产顶层来源标签不证明其中每个细节都是原文事实；原文只写骷髅刺绣而未写颜色时，颜色属于设计补充。
4. **核对最终提交稿**：从本图应体现和不得提前出现的剧情条件查到最终实际提交正文或职责明确、实际已核验的参考，再反查正文新增的剧情信息是否有出处或授权。依据说明里写对了、正文或实际输入漏传了，仍需修订；精简、翻译和返修后复核这条对应关系。参考未显示的内容不能作为已覆盖证据。
5. **同时对照依据与图片**：先确定相关正文／采用事件、当前设计与时点，再看实际提示词和图像。分别定位上游提取错误、补全越界、提交漏项或生成未遵循；完整图片内容审查覆盖本用途必要的剧情条件及可见部位，并在审核 `scope`／`evidence` 中写清实际依据、检查范围与结论。图像美观、跨图一致或工具通过不能抵消关键剧情错误，未查看或不可辨项保留限制。

制作中发现出场清单遗漏、旧设计差异或来源误标时，列出正文位置、差异、受影响用途及下一动作，按“纠错汇入与当前基准”处理。在本轮已授权保存／交接范围内写入现有 REPORT 的 `pending_actions`／`next_actions`，将实际使用的上游精确版本放在现有 `refs`／`data`；工具不会从附件文字自动建立依赖或同步清单。

## 四、登记、审核与对账

工具保存快照、明确采用和登记审核是不同操作。工作稿可以先预审、修订并形成建议采用意见；正式操作先保存准确快照，再核对该快照及必要依据、登记审核，最后使用 `adopt --review <实际审核ID>` 绑定准确ID、版本与哈希采用。预审后内容有变化须复查，文字认可不表示已登记审核或改变采用指针。

同一快照的完整通过审核建立有效依据，后续局部通过只补充证据；后续需修订或待核实会阻断，必须新的完整通过审核才能恢复，不能用旧稿或更早通过记录绕过。AI实际判断记 `ai`；实际由人类完成与 `scope` 匹配的阅读、看图、播放或听音检查，并有可追溯意见才记 `human`。AI代为整理时只登记该人的真实检查范围，不将AI自己的判断记成人工审核；用户仅阅读AI报告不证明亲自检查了媒体。

文字内容审核先按用户目标读取实际稿件和必要来源、形成有位置依据的判断，再参考作者解释与自检结论，按[16内容审核](../技能库/16_内容审核技能.md)分别判断来源与连续性、人物与叙事取舍、观看／阅读节奏、视觉表达和制作可行性。用户要求留住观众、展示制作水平时，未达目标是需修订，不能降为可选润色后整体通过；先读实际连续动作与信息，再估正常表演时间。完整阅读、哈希正确、功能齐全、字数少和时间相加正确都不能单独证明好看。已授权修订须交实际修改内容；文字阶段可定位的拖沓不全部留给读演解决。预测风险与已证实的来源错误分别记录，不为证明审核独立而强找问题；全部通过须有对应内容证据，不能只复述作者理由。

正式导出使用现有 `export --require-review`，按实际所选范围交付。这项工具约束针对播放章节，不等于图片、视频、声音或成片门禁。技能执行时另查本轮正式取用的媒体与成片证据；只有文字完成时可以交文字包，不能将它报作媒体验收或发布完成。当前工具可读取已有旧布局项目和历史包，不为满足新规则批量改旧记录。

人读清单、台账和工具状态的对账由AI或人实际执行，当前工具不会自动同步。需要清单时，以当次读取的采用指针、快照 `data.files` 和实际文件生成摘要，写明读取时点、版本及未查范围；发现手填清单滞后，报告差异。更新原清单只有属于本轮已授权工作才写回，不把候选、未上传或未验收转成完成。

没有SHOT来源的独立定妆或场景图片不虚构SHOT、EP、SC或PROMPT来凑生产链。完整图片提示词和来源可以保存为对应MEDIA附件；只有取得真实文件后才登记MEDIA。已有镜头时按协议建立SHOT → 图片PROMPT → 实际图片MEDIA → 视频PROMPT → 实际视频MEDIA关系。

生成与返修用[17台账](../模板库/17_生成与返修台账模板.md)，后期取用用[18剪辑交接](../模板库/18_剪辑取用与转场交接模板.md)。它们是人读附件，编号不自动加入依赖，不能据此声称机器已校验尝试、费用或成片时间轴。需交接的基准与成果明确登记于REPORT的 `refs`／`data`，失败证据按现有规则作为附件冻结。

准备或基准REPORT只引用实际上游依据；结果或返修REPORT引用实际成果，不让MEDIA反向引用包含自身结果的REPORT。SHOT不反向引用自己的衍生提示词或媒体，避免循环。历史尝试和失败链不覆盖，已有REPORT更新用新版本。

### 失败与恢复

| 实际状态 | 下一动作 |
| --- | --- |
| 本地写操作中断或返回异常 | 先查状态；有待恢复事务时用 `recover --project <项目目录>` 纯恢复，再核对原登记与输出，不靠新建资产或盲目重试触发恢复 |
| 恢复已完成，但后续请求失败 | 保留并报告 `recovered_transaction`、`recovered_lock` 及原错误；失败不表示没有写入，不因此直接升版或重复导出 |
| 阅读视图已生成但根链接未通过 | 报告实际 `output` 和 `root_issues`，保留诊断产物；生成结果与检查结论分别表达 |
| 外部生成、上传或发布已提交但超时、断线或结果不明 | 记“提交结果待核实”，保留可取得的任务编号、提交时间及输入定位，先查原任务、草稿或公开状态；无法确认时不直接重发 |
| 明确输入或格式错误；限流或服务暂不可用 | 输入错误先修输入；限流按平台实际提示等待，不原样反复提交 |
| 已取得结果但内容未通过 | 定位实际问题后进入现有最小返修，复查新结果才关闭问题 |

需要新增提交时沿用本轮授权、尝试和预算边界。有硬预算时，提交前合计已结算、仍可能计费的在途任务与本次可确认消耗；预计超限不新增消费。未知费用保留未知，先完成不消费的工作。活动、异机或无法验证的锁不解除；恢复声明再次中断只由纯恢复入口在验证后接替，具体操作见[部署说明](部署说明.md)。

## 五、证据与完成条件

| 实际完成的检查 | 可以报告的结论 | 仍需保留的范围 |
| --- | --- | --- |
| 读取文本、配置、快照或工具返回 | 该版本文字、结构、路径与记录情况 | 未看的图、未听的音、未播放的视频 |
| 查看图片或视频抽帧 | 所看画面、部位和时点的静态表现 | 帧间动作、整段稳定性与声音 |
| 连续播放视频或听取音频 | 实际覆盖区间的动作、内容、连续性或声音 | 未覆盖区间和工具无法辨认的内容 |
| 剪映工程操作、导出与观看 | 实际操作、导出文件及检查过的成片范围 | 未执行后期、未检查声轨或未完成发布 |

文件存在、工具测试通过、媒体已采用、平台接收请求都不能代替真实视听检查。问题应定位到具体文件、图片区域或素材时码；成片时码另列，不把设计秒点当实测。没有新结果不关闭媒体返修。工作室预算、尝试上限与期望产能来自用户目标和实测，不编平台价格、成功率或费用。

## 六、并行制作与交接

并行前声明本轮项目、品类、资产ID及文件写入范围；修改共同基准、`project.json`或共享清单前重新读取状态并协调归属。工具锁只保护单次登记操作，不保护各会话的手工文件修改；不擅自删锁、替他人采用或回滚并行新增内容。

维护共享规则时仅编辑已约定的规则范围；故事工作稿、采用指针、历史快照、备份和个人配置不随之改变。交接包含当前采用基准、实际成果位置、视听检查覆盖、未解决问题及下一动作。跨会话继续时重新读取文件，不假设聊天记忆仍代表当前状态。

优先直接填写正式工作资产。确需并行准备时，同一任务只使用 `production/.staging/<任务标识>/` 一个受控位置，声明负责人和文件归属；汇入正式资产并核对后停止双份维护。旧准备稿清理先列确切候选及与正式稿的对应证据，未获删除授权不执行。操作结果和复核证据集中于工具记录及必要的现有REPORT，不为同一完成状态新增多份同义报告或清单；真实审核输入、记录和失败证据保留。同一交接包的派生阅读视图复用包内精确冻结资产；另需跨机携带时才生成独立便携视图。减少文件不靠删快照、跳审核、改哈希或引用浮动最新版。

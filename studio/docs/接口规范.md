# 本地接口规范

## 工作室技能的调用约定

当前入口管理布局v2及布局v1兼容项目。v2采用必须绑定精确版本的完整通过审核，正式漫改导出默认且强制检查播放章节审核；这不等于图片、声音或成片已通过视听验收。

工作室管理与制作命令入口为工作区根的 `studio/bin/studio.mjs`，由当前 AI 在工作区根目录调用；用户通过对话提出任务，无需操作终端或菜单。路径或理由含空格时加双引号。无参数或 `--help` 仅显示帮助，各命令可加 `--json` 返回机器可读 JSON。字段规范只见[数据协议](数据协议.md)。

中文命令与英文别名使用同一入口及实现，不另设中文启动文件。中文目录导航见[工作室入口](../../工作室入口.md)。

## AI 制作上下文、提示词与任务续跑

现有 `制作上下文` 支持可选创作任务说明和必读正文要求；返回缺失必读项时失败，不将摘要当全文。现有 `编译提示词` 支持固定视觉组件、明确参考职责及镜头动态状态，拒绝用镜头描述覆盖已锁设计。机器字段及错误边界统一见[数据协议的工业化扩展](数据协议.md#工业化创作与固定视觉扩展)，没有增加后台代理、外部模型调用或新命令入口。

以下请求文件由当前 AI 根据真实小说和精确资产版本生成，用户无需填写 JSON 或逐镜提示词。实际步骤见[AI制作流程](AI制作流程.md)，字段见[数据协议](数据协议.md)。路径相对 `--project`，下列项目及文件名只是示例，先替换为真实值。

```powershell
node studio/bin/studio.mjs 制作上下文 --project projects/IP编号_项目名 --file production/.staging/第一集/上下文请求.json --json
node studio/bin/studio.mjs 预填资产 --project projects/IP编号_项目名 --file production/.staging/第一集/预填请求.json --json
node studio/bin/studio.mjs 编译提示词 --project projects/IP编号_项目名 --file production/.staging/第一集/镜头编译请求.json --out production/制作准备/第一镜 --json
node studio/bin/studio.mjs 解析连续状态 --project projects/IP编号_项目名 --file production/.staging/第一集/状态请求.json --json
node studio/bin/studio.mjs 检查制作成果 --project projects/IP编号_项目名 --file production/.staging/第一集/检查请求.json --out production/制作准备/本次检查 --json
node studio/bin/studio.mjs 修复制作成果 --project projects/IP编号_项目名 --file production/.staging/第一集/修复请求.json --out production/制作准备/本次修复 --json
node studio/bin/studio.mjs 创建制作任务 --project projects/IP编号_项目名 --file production/.staging/第一集/制作计划.json --json
node studio/bin/studio.mjs 制作任务状态 --project projects/IP编号_项目名 --json
node studio/bin/studio.mjs 登记制作成果 --project projects/IP编号_项目名 --file production/.staging/第一集/成果批次.json --json
```

| 中文命令 | 英文别名 | 实际行为 |
| --- | --- | --- |
| 制作上下文 | `production-context` | 按精确版本、事件、局部字段、冻结附件或原稿行范围只读组装上下文；可只保留依赖身份，超字符预算返回失败和省略清单。 |
| 预填资产 | `seed-production-asset` | 复用现有骨架，继承明确上游引用，不写工作资产、不推断创作内容。 |
| 编译提示词 | `compile-prompts` | 从 SHOT 及精确资产编译中文稿与依据，缺项交回当前 AI 补全，不调用模型或保存资产。 |
| 解析连续状态 | `resolve-continuity-state` | 在明确 STATE 边界只读求值，返回逐属性来源及未决项；旧自由文本不猜顺序。 |
| 检查制作成果 | `check-production` | 检查候选与所选冻结版本的结构、时间轴、明确连续性和托管提示词；不登记内容审核。 |
| 修复制作成果 | `repair-production` | 对克隆候选有限修复并重新检查；保留修改痕迹，未保存、未审核、未采用。 |
| 创建制作任务 | `create-production-task` | 将固定阶段计划保存为 REPORT 候选快照；相同请求标识和内容复用原计划。 |
| 制作任务状态 | `production-task-status` | 从计划、成果回执、快照和实际审核采用派生状态；可用成对 `--asset`、`--version`，或 `--file` 中的 `task` 查询单任务。 |
| 登记制作成果 | `import-production-results` | 按依赖顺序保存真实文本成果；同批次重试复用已保存结果，修订走保留原稿的事务。 |

上下文、预填、编译及新增的解析／检查／修复默认仅返回内存结果，可选 `--out` 写入 v2 的 `production/制作准备/<新目录>` 或 v1 的 `00_项目管理/制作准备/<新目录>`。目标已存在、越界或包含正式资产时拒绝覆盖。失败的上下文／编译不输出完整成果目录；解析／检查／修复可在失败时导出诊断与候选，仍保持失败退出码并明示检查未通过。请求字段及返回值见[数据协议](数据协议.md)。当前 AI 调用 `制作任务状态` 查看任务与下一阶段，再继续执行创作。

制作上下文需要附件实际正文时，AI 在请求中用 `asset_readings` 指定冻结版本和文件，核对返回文本与完整／选段范围；附件目录不算读取。资产过大时使用 `data_selections` 定位已有字段或条目，并以 `dependency_mode: references` 保留依赖身份、另选本用途必要内容。检查未读附件提示和省略项；预算完整只对应所选请求，不替代剧情选材判断。字段及例外统一见数据协议。

成果登记先检查整批及同阶段既有成果，确定问题通过 `quality` 返回，未通过前不新增本批写入；部分范围不会自动按整集检查。修复候选经宿主 AI 实际核查后再登记，已冻结成果修改仍须新版本和新批次。重复提交原请求及实际写入中断的恢复机制保持。制作任务的“需修订”由当前检查派生，不能手填成已通过，也不能替代完整内容审核与采用。

任务默认四阶段可以按实际缺口裁剪。每阶段 `expected_types` 是允许登记的类型，不是镜头数或内容质量承诺；当前 AI 必须核对本轮目标完整性，正式交付仍走已有播放链与审核约束。不为复用已有剧本而重新生成相同资产。正文内容、逐镜视觉选择和参数由 AI 按技能完成，程序不会把空骨架自动标成创作完成。

批次部分成功时返回已保存成果和错误；先查询／恢复实际事务，再用完全相同请求续跑。变更内容使用新 `batch_id` 及明确新版本，不能覆盖已冻结版本。若未完成批次的前序成果已变化，旧批次拒绝续跑盖上新依据，AI 应核对并修订相关成果。工作稿与 `base_version` 不同会拒绝修订；原工作稿保存在本次事务的 `原工作稿/<资产ID>/` 中。入口不会自动登记审核、采用、上传或发起计费。

## 创建项目

```powershell
node studio/bin/studio.mjs init --root projects --id IP003 --name 新故事
```

当前 AI 通过 `init` 命令或公开函数 `initProject` 默认创建布局v2的独立项目目录、项目清单及空白骨架。旧布局验证夹具可显式传 `--schema 1` 或 `schemaVersion: 1`，`--schema 2` 显式选择v2。已有目标拒绝覆盖。`--root` 是项目父目录，`--id` 是 IP 编号，`--name` 是项目名。初始化成功不代表已有完整小说或漫改成果。

## 小说接入与选章阅读

通用入口为 `studio/bin/novel-intake.mjs`，不写项目登记、不保存正式资产、不审核或采用。以下路径是占位示例，先替换为实际输入及不存在的输出目录：

```powershell
node studio/bin/novel-intake.mjs ingest --input "原稿.txt" --output "projects/IP编号_项目名/sources/本次接入" --encoding utf-8 --split separator --separator "------------"
node studio/bin/novel-intake.mjs verify --catalog "projects/IP编号_项目名/sources/本次接入/intake.json"
node studio/bin/novel-intake.mjs read --catalog "projects/IP编号_项目名/sources/本次接入/intake.json" --chapters 1-3 --output "projects/IP编号_项目名/production/.staging/本轮/取材" --clean-html
```

`ingest` 显式指定编码；不传 `--split` 时只存档，`heading` 按章标题分段，`separator` 按明确分隔行分段。自定义标题、包装与广告识别用 `--heading-pattern`、`--packaging`、`--ad-pattern`；广告识别只标异常，不删原稿。索引格式由[数据协议](数据协议.md)定义。`verify` 只读核验原稿、片段及重建一致性，兼容现有IP003的 `sources/章节索引.json`，不要求重导。

`read` 必须给物理序范围（如 `1-3,5`），拒绝 `all`／`*`；只有所选章产生阅读文本和来源追溯。`--clean-html` 只移除白名单标签／注释边界并解码实体，段落与br/hr保留换行，未知标签样式原样保留并定位提示，script/style／注释文字及疑似广告保留；另传 `--plan` 时，JSON含 `rules` 数组，以 `{"kind":"literal","text":"已确认广告原文","replacement":""}` 指明清理项。项目内接入仅写全新sources子目录，选章阅读仅写 `production/.staging/<任务标识>/`；禁止写冻结、正式资产、历史、备份和发行目录。清理结果不自动成为正式CH；本轮取材需正式来源时，沿用下节的 `new-asset`，直接填写七文件和来源定位，再保存准确版本。原稿、分章和现有项目不会被这些命令覆盖。

## 创建资产骨架与查看状态

```powershell
node studio/bin/studio.mjs new-asset --project projects/IP003_新故事 --type WORLD --title 世界规则
node studio/bin/studio.mjs new-asset --project projects/IP003_新故事 --type CHAR --title 主角
node studio/bin/studio.mjs new-asset --project projects/IP003_新故事 --type CH --title 第一章
node studio/bin/studio.mjs status --project projects/IP003_新故事
```

`new-asset` 支持协议中的13类资产，自动取该类型下一个编号并选择目录；v2使用 `assets/<TYPE>/<ID>/`；可用 `--sequence 003` 明确序号。它创建并登记工作骨架，历史版本为空、尚未采用，不覆盖已有ID或目录。CH同时创建七文件。由AI按技能和数据协议填实际内容，不能把空骨架当作已完成创作。已登记资产随后可直接 `save-version --asset`。

`status` 只读显示工作版本、采用版本、未保存变化、待办与复核编号，适合打开项目或新对话时先查看。`pending` 是保存、采用、审核和版本复核等工具待办；它为空不代表报告里的创作、预演或媒体任务已经完成，也不替代 `validate`。

## 恢复中断操作

```powershell
node studio/bin/studio.mjs recover --project projects/IP003_新故事 --json
node studio/bin/studio.mjs status --project projects/IP003_新故事 --json
```

`recover` 和公开函数 `recoverProject({ project })` 复用既有锁与事务完整性校验，只恢复已存在的事务或可验证失效锁，不新建资产、重复审核、采用或生成交付包。无待恢复事务也正常成功。中断后优先纯恢复，再查原资产、版本和输出，不能靠重复业务命令触发恢复并假定只会执行一次。

普通写入保留自动恢复兼容；遇到已中断的恢复声明时只指向 `recover`。该入口必须验证同机原进程和恢复进程均已退出、旧锁未变，才能保留旧证据并追加唯一接替声明；活动、异机、损坏或无法验证的锁仍拒绝。成功和异常中保留实际 `recovered_transaction`、`recovered_lock`，字段形状见[数据协议](数据协议.md)，现场核对见[部署说明](部署说明.md)。

## 检查

```powershell
node studio/bin/studio.mjs validate --project projects/IP003_新故事
node studio/bin/studio.mjs validate --project projects/IP003_新故事 --strict
```

普通检查用于工作稿：检查格式、ID、路径、引用、章节文件和历史完整性，对未完成内容给出位置与提示。`--strict` 用于准备采用的内容检查，要求正文和各类最低内容完整。检查不会创作或补齐资料，不修改工作稿；只读检查发现中断事务时报告需恢复。

声明 `reference_bindings` 的PROMPT还检查MEDIA精确快照中的具体文件及可选用途匹配；字段与兼容规则见[数据协议](数据协议.md)。无新字段的旧提示词继续可用；旧绑定未声明用途要求会提示“未启用用途匹配”。检查、保存、采用、漫改导出和续作包保留相关 `warnings`，路径错误定位到具体绑定项。工具不自动识别图片内容或执行剪辑附件。

## 保存版本

```powershell
node studio/bin/studio.mjs save-version --project projects/IP003_新故事 --path assets/CH/IP003-CH-001
node studio/bin/studio.mjs save-version --project projects/IP003_新故事 --asset IP003-CH-001
node studio/bin/studio.mjs save-version --project projects/IP003_新故事 --asset IP003-CH-001 --reason "补足钥匙交还事件并同步人物状态"
```

`new-asset` 已登记的骨架用 `--asset` 保存；外部创建的目录首次可用 `--path` 读取 `asset.json` 登记。两个参数不能同时传。版本号取自工作资产的 `version`；保存草稿不等于采用，保存同一版本拒绝覆盖。无效引用、非法路径、缺章节文件必须修复后再保存；草稿可以保留空正文和合法的空 JSON 对象/数组，JSON 文件本身不能留白。

保存章节时会冻结整个工作目录，因此正文和六份 JSON 必须同步。上游资产先保存，才能在下游引用其确定版本。

`--reason` 可选，记录本次保存或修订依据；未填时使用“保存本轮工作稿快照”。有实际修订时建议填写具体内容，工具将其写入快照清单及操作日志。保存理由不是采用理由，不能省掉后续采用操作。

## 记录针对确切版本的内容审核

```powershell
node studio/bin/studio.mjs record-review --project projects/IP003_新故事 --asset IP003-CH-001 --version 1.0.0 --file production/review-inputs/首章审核输入.json
```

先实际阅读已保存章节及其依赖，再由审核者填写输入文件；文件必须位于该项目内，字段以[数据协议](数据协议.md)的“内容审核证据”为准。工具绑定快照ID、版本与哈希，返回 `review_id` 并冻结记录。它不自动阅读故事，不自动宣称人工审核。

审核输入区分 `ai` 与 `human`，包含范围、完整/局部覆盖、结论、问题和实际证据。只改稿还未复查的问题不能标解决；有未解决阻塞或应修订问题时不能记录通过。工作稿可先预审，但正式审核绑定已保存快照；采用审核约束要求完整覆盖且通过，不能用旧稿审核或局部检查代替新版本完整审核。

## 采用版本

```powershell
node studio/bin/studio.mjs adopt --project projects/IP003_新故事 --asset IP003-CH-001 --version 1.0.0 --reason "依据本章完整审核记录采用" --review REV-实际返回的编号
```

明确选择已保存版本，严格核对该快照及其依赖；依赖版本必须曾采用。采用理由填写实际检查依据，不把示例理由照抄成未经执行的事实。操作记录采用时间和版本；工作稿中的标签不替代本命令。新采用版本会提示受影响的下游，保留它们原来的内容及引用。

命令中的审核编号须换成实际 `record-review` 返回值。带 `--review` 时核查精确版本与哈希的有效完整通过证据。按登记顺序，后续局部通过只补证；后续需修订或待核实会阻断，必须在其之后产生新的完整通过。显式编号也须完整通过且位于最近阻断之后，不能指定局部记录或旧通过编号绕过。布局v2必须带 `--review`；布局v1不带参数仍可兼容执行并提示未绑定审核，不得据此认定内容通过。

## 处理“保留历史引用”的复核项

```powershell
node studio/bin/studio.mjs status --project projects/IP003_新故事 --json
node studio/bin/studio.mjs review-item --project projects/IP003_新故事 --item RI-状态返回的完整编号 --reason "保留旧版的实际理由" --evidence "实际核对的位置、内容及结论" --method ai --reviewer "实际审核者名称"
```

替换状态返回的完整复核编号，并填写实际理由、证据和审核者；`--method` 为 `ai` 或 `human`，理由与证据都必填。工具从该项取精确上下游版本和间接路径，只处理这一次变化。上游或路径再次变化会产生新项；要跟随新版时实际修改下游引用、保存并采用新版本，不用此命令假装已经改稿。

## 导出交接

```powershell
node studio/bin/studio.mjs export --project projects/IP003_新故事 --out deliveries/handoff/交接包1
node studio/bin/studio.mjs export --project projects/IP003_新故事 --episodes IP003-EP-001 --require-review --out deliveries/handoff/第一集交接包1
node studio/bin/studio.mjs export --project projects/IP003_新故事 --chapters IP003-CH-001 --out deliveries/handoff/所选章节漫改包1
```

`--out` 为v2项目 `deliveries/handoff/` 下的相对目录；v1仍用 `07_发布资产/`，目标必须不存在，且不能与工作资产目录相互包含。项目必须有已采用 CH、EP、SC、SHOT，且其依赖都曾采用。工具导出当前采用资产和完整依赖闭包，允许固定使用历史曾采用版本并提示复核，绝不从新工作稿偷偷补内容。

默认全项目导出；`--episodes` 和 `--chapters` 互斥，均接受逗号分隔的完整资产ID。按章节会选中使用这些章节的整集，可能带入同集其他章节。范围外内容作为必要来源证据进入包，不因此成为新增播放镜头。关联报告或提示词跨出所选制作范围时会警告，可拆分该资产或扩大范围；不要忽略警告而称完整交接。

`--require-review` 要求本次实际播放章节的每个版本具有精确快照的有效完整通过记录，自动选取最近有效完整记录，局部补证不会替换它。v2始终启用；v1未传此选项时保留兼容方式并提示审核缺口。纯小说还没有EP、SC、SHOT时使用下面的 `resume`，不要虚构分镜来凑导出条件。

布局v2执行完整审核约束，不能关闭；布局v1需显式传 `--require-review`。当前 AI 进行正式导出时启用该参数，选择写入导出记录。

每个章节 ID 都需要对应分集，每个剧集 ID 需要场次，每个场次 ID 需要镜头。全新章节或场次没有下游时须补齐；同一 ID 的新版尚未重新桥接，但历史曾采用版已有完整制作链时，允许保留历史链导出并提示复核。包内新版资料不代表旧分镜已经跟随修改。当前播放时间轴不支持重叠镜头，叠化等方案仍按原技能手动交接，不能只改时间数字绕过实际冲突。

实际播放树仅使用当前采用镜头及其场次、剧集引用；历史镜头依赖保留在资产包中，不重复播放。`--json` 的导出结果带 `playback`，同 ID 新采用版尚未被当前镜头使用时会列入 `playback.uncovered_adopted_versions` 并返回 `warnings`。同一播放树不能混用同一剧集或场次的多个版本。

| 结果文件 | 用途 |
| --- | --- |
| `handoff.json` | 程序读取结构化交接 |
| `交接说明.md` | 人工阅读；可交给原 00、06—09 技能 |
| `来源与版本清单.json` | 核对实际使用 ID、版本与来源 |
| `内容审核记录.json` | 本次播放章节的真实审核记录；与结构成功分别看待 |
| `assets/` | 该交接使用的完整资产快照 |

## 生成小说阶段续作包

```powershell
node studio/bin/studio.mjs resume --project projects/IP003_新故事 --out deliveries/resume/续作包1
```

不要求先完成漫改。输出目录必须是v2 `deliveries/resume/` 下的新目录；v1仍用 `00_项目管理/`，不得与工作资产相互包含。包内有 `续作说明.md`、`续作信息.json` 和实际采用快照，包含设定、状态、章节、读取清单、工具待办和审核记录；未采用工作稿只列状态与问题，不混入采用正文。所打包快照的检查警告同时出现在命令 `warnings`、续作信息 JSON 及中文说明。

默认不额外生成REPORT阅读视图。确需重定位链接时加 `--reading-views`（API `readingViews: true`）；视图复用包顶层 `assets/` 的固定快照，不在每个REPORT目录再复制依赖。`续作信息.json`、操作结果与续作记录中的 `reading_views` 表明本次选择。v2漫改export仍生成阅读视图，同样复用包内资产。

把续作包位置和本次目标交给新对话，要求实际读取其中的精确版本。若原项目后来继续变更，先重新查看状态再决定是否生成新包。每次使用新输出目录，旧包保留当时的交接记录。

## 失败与返回

失败信息应保留问题路径和原因；先核对已发生的恢复、登记及实际输出，再决定修工作稿、引用或调用参数后重试。不要因一次失败更改历史快照、伪造采用记录或直接升版。已有项目、快照或导出目录不覆盖；确认其归属后，有新的业务成果才使用新的编号、版本或输出目录。

工具异常表示请求未正常结束，不保证没有写入，也不代表故事审核失败；工具成功不代表文学或成片质量通过。纯恢复成功只说明既有事务或锁已处理。锁、事务与备份说明见[部署说明](部署说明.md)，外部提交未知时的核查与重试见[工作室执行规则](工作室执行规则.md)。

命令成功退出码为 `0`，检查未通过或操作异常为 `1`。JSON 返回至少带 `ok`；操作异常含 `errors`，检查可含 `warnings`、`stats` 或具体问题数组，采用或导出可含 `review_items`。根链接未通过的阅读视图可已生成，此时 `ok: false`、`errors: []`、`output` 和 `root_issues` 分别定位产物与检查问题；致命生成异常保留错误及可能不完整的输出路径。实际恢复返回 `recovered_transaction`／`recovered_lock`，即使后续请求失败仍保留；附加清理错误放 `cleanup_errors`，不遮掉原错误。按显式字段判断，不仅搜索“完成”或仅凭退出码推断是否发生写入。

## 链接审计与派生阅览报告

```powershell
node studio/bin/studio.mjs audit-links --project projects/IP003_新故事 --json
node studio/bin/studio.mjs render-report --project projects/IP003_新故事 --asset IP003-REPORT-001 --version 1.0.0 --out deliveries/views/报告1 --json
node studio/bin/studio.mjs render-report --project projects/IP003_新故事 --asset IP003-REPORT-001 --version 1.0.0 --mode portable --out deliveries/views/便携报告1 --json
```

`audit-links` 的工作分支读取实际工作 `asset.json`、附件及自身精确依赖，冻结分支读取正式采用版本的冻结清单与依赖。版本身份、未保存状态及链接目标身份的字段见[数据协议](数据协议.md)。迁移后的遗留相对路径沿用该工作版本的来源路径或已验证迁移映射，不借用采用版依赖、不猜选最新版本。

链接审计检查当前已采用REPORT的工作附件与对应冻结Markdown，分别报告原始路径失效、经精确依赖和迁移映射可解析，以及仍无法解析的链接；不扫描所有项目Markdown，也不改写冻结正文。派生报告必须输出到deliveries/views下不存在的新目录，包含阅读说明.md、view.json和reports派生Markdown。`--mode local` 为默认：直接引用 `.ip-system/snapshots/<ID>/<版本>/`，不复制assets；移动视图或项目后须重建。`--mode portable` 才复制完整冻结assets，适合独立携带。两种模式的view.json及结果记录 `mode`、根来源哈希与 `sources` 中的固定ID、版本、manifest_sha256及路径，不引用浮动工作稿。显式指定已保存版本时可阅览未采用REPORT，但不因此将它纳入正式交接或采用。输出只作阅读副本，不登记新资产、不替换采用基准、不回写快照，也不证明素材实际看检。未声明精确版本依赖或同ID多版本含糊时保留问题，不猜选最新文件。

`render-report` 返回 `root_issues`（选定根REPORT内的问题）及 `historical_issues`（递归引用的其他REPORT说明中的问题），每项包含 `asset_id`、`version`、`file`、一基 `line`、`raw_link`、`reason`、`scope: "root" | "historical"` 和 `issue_page`。两类问题都进入 `warnings` 与view.json；根问题非空时 `ok: false`，仅有递归说明问题时可返回 `ok: true` 并保留历史限制。致命结构、完整性或IO异常仍返回 `ok: false` 与 `errors`，不会降为历史警告。

未定位链接仅在派生Markdown改指 `link-issues/<问题ID>.md` 诊断页，标签附“未定位链接说明”；未定位图片改为普通诊断链接。诊断页不是素材，原文及原始链接完整保留于精确快照（便携模式另有assets副本），不选择替代素材、不补造版本或依赖。单报告的 `issue_page` 相对输出视图目录；包顶层问题数组的路径相对包目录，包内报告自身记录的路径相对该报告视图目录。包派生视图按相同根/递归分类报告，阅读可用不意味着历史素材全部已定位或验收。

## 未采用候选停用与恢复

```powershell
node studio/bin/studio.mjs retire-asset --project projects/IP003_新故事 --asset IP003-MEDIA-002 --reason "本用途改用另一个候选，保留失败证据" --json
node studio/bin/studio.mjs restore-asset --project projects/IP003_新故事 --asset IP003-MEDIA-002 --reason "重新评估该候选用于另一个视图" --json
```

仅布局v2支持。任何曾采用过的资产，或被已采用下游引用的候选，均拒绝停用/恢复。工具在登记项保存lifecycle（active或retired，省略按active）并追加lifecycle_history；不改变采用指针、不删除文件或快照、不改来源/采用语义。status仍列出全部资产及retired列表，退役候选退出drafts和行动pending；继续保存/采用前先restore，恢复本身不表示审核或采用。

### 用户已删除候选工作目录后的登记清理

```powershell
node studio/bin/studio.mjs 清理已删候选 --project projects/IP003_新故事 --assets IP003-MEDIA-001,IP003-MEDIA-002 --reason "用户已删除弃用候选工作目录，清理失效登记" --json
```

英文别名为`cleanup-deleted-assets`。只处理布局v2中工作目录已不存在、已退役且从未采用的明确候选。任何其他工作资产或历史快照仍引用这些ID时拒绝清理，不自动删引用或改历史。成功仅移出现行`assets`登记，将原登记完整保存在本次真实操作记录中；保留历史文件、审核、采用与生命周期记录。新建资产继续保留历史编号，自动取后续编号，显式重用也拒绝。它不负责删除工作文件或快照，不能用于已采用资产。

# 本地接口规范

## 工作室技能的调用约定

当前入口管理布局v2及布局v1兼容项目。v2采用必须绑定精确版本的完整通过审核，正式漫改导出默认且强制检查播放章节审核；这不等于图片、声音或成片已通过视听验收。

实现入口为工作区根的 `studio/bin/studio.mjs`。在工作区根目录运行下列命令；路径或理由含空格时加双引号。没有参数时打开中文菜单，`--help` 查看用法，各命令可加 `--json` 返回机器可读 JSON。菜单和命令行共用检查、保存、采用与导出逻辑。字段规范只见[数据协议](数据协议.md)。

## 创建项目

```powershell
node studio/bin/studio.mjs init --root projects --id IP003 --name 新故事
```

默认创建布局v2的独立项目目录、项目清单及空白骨架。可传 `--schema 1` 创建兼容布局，`--schema 2` 显式选择v2。已有目标拒绝覆盖。`--root` 是项目父目录，`--id` 是 IP 编号，`--name` 是项目名。初始化成功不代表已有完整小说或漫改成果。

## 创建资产骨架与查看状态

```powershell
node studio/bin/studio.mjs new-asset --project projects/IP003_新故事 --type WORLD --title 世界规则
node studio/bin/studio.mjs new-asset --project projects/IP003_新故事 --type CHAR --title 主角
node studio/bin/studio.mjs new-asset --project projects/IP003_新故事 --type CH --title 第一章
node studio/bin/studio.mjs status --project projects/IP003_新故事
```

`new-asset` 支持协议中的13类资产，自动取该类型下一个编号并选择目录；v2使用 `assets/<TYPE>/<ID>/`；可用 `--sequence 003` 明确序号。它创建并登记工作骨架，历史版本为空、尚未采用，不覆盖已有ID或目录。CH同时创建七文件。由AI按技能和数据协议填实际内容，不能把空骨架当作已完成创作。已登记资产随后可直接 `save-version --asset`。

`status` 只读显示工作版本、采用版本、未保存变化、待办与复核编号，适合打开项目或新对话时先查看。`pending` 是保存、采用、审核和版本复核等工具待办；它为空不代表报告里的创作、预演或媒体任务已经完成，也不替代 `validate`。

## 检查

```powershell
node studio/bin/studio.mjs validate --project projects/IP003_新故事
node studio/bin/studio.mjs validate --project projects/IP003_新故事 --strict
```

普通检查用于工作稿：检查格式、ID、路径、引用、章节文件和历史完整性，对未完成内容给出位置与提示。`--strict` 用于准备采用的内容检查，要求正文和各类最低内容完整。检查不会创作或补齐资料，不修改工作稿；只读检查发现中断事务时报告需恢复。

声明 `reference_bindings` 的PROMPT还检查MEDIA精确快照中的具体文件及可选用途匹配；字段与兼容规则见[数据协议](数据协议.md)。无新字段的旧提示词继续可用；旧绑定未声明用途要求会提示“未启用用途匹配”。检查、保存、采用、漫改导出和续作包保留相关 `warnings`，路径错误定位到具体绑定项。工具不自动识别图片内容或执行剪辑附件。

## 保存版本

```powershell
node studio/bin/studio.mjs save-version --project projects/IP003_新故事 --path assets/CH/IP003-CH-001
node studio/bin/studio.mjs save-version --project projects/IP003_新故事 --asset IP003-CH-001
node studio/bin/studio.mjs save-version --project projects/IP003_新故事 --asset IP003-CH-001 --reason "补足钥匙交还事件并同步人物状态"
```

`new-asset` 已登记的骨架用 `--asset` 保存；外部创建的目录首次可用 `--path` 读取 `asset.json` 登记。两个参数不能同时传。版本号取自工作资产的 `version`；保存草稿不等于采用，保存同一版本拒绝覆盖。无效引用、非法路径、缺章节文件必须修复后再保存；草稿可以保留空正文和合法的空 JSON 对象/数组，JSON 文件本身不能留白。

保存章节时会冻结整个工作目录，因此正文和六份 JSON 必须同步。上游资产先保存，才能在下游引用其确定版本。

`--reason` 可选，记录本次保存或修订依据；未填时使用“保存本轮工作稿快照”。有实际修订时建议填写具体内容，工具将其写入快照清单及操作日志。保存理由不是采用理由，不能省掉后续采用操作。

## 记录针对确切版本的内容审核

```powershell
node studio/bin/studio.mjs record-review --project projects/IP003_新故事 --asset IP003-CH-001 --version 1.0.0 --file production/review-inputs/首章审核输入.json
```

先实际阅读已保存章节及其依赖，再由审核者填写输入文件；文件必须位于该项目内，字段以[数据协议](数据协议.md)的“内容审核证据”为准。工具绑定快照ID、版本与哈希，返回 `review_id` 并冻结记录。它不自动阅读故事，不自动宣称人工审核。

审核输入区分 `ai` 与 `human`，包含范围、完整/局部覆盖、结论、问题和实际证据。只改稿还未复查的问题不能标解决；有未解决阻塞或应修订问题时不能记录通过。采用审核约束要求完整覆盖且通过，不能用旧稿审核或局部检查代替新版本完整审核。

## 采用版本

```powershell
node studio/bin/studio.mjs adopt --project projects/IP003_新故事 --asset IP003-CH-001 --version 1.0.0 --reason "依据本章完整审核记录采用" --review REV-实际返回的编号
```

明确选择已保存版本，严格核对该快照及其依赖；依赖版本必须曾采用。采用理由填写实际检查依据，不把示例理由照抄成未经执行的事实。操作记录采用时间和版本；工作稿中的标签不替代本命令。新采用版本会提示受影响的下游，保留它们原来的内容及引用。

命令中的审核编号须换成实际 `record-review` 返回值。带 `--review` 时核查精确版本与哈希的最新完整通过证据；同快照后来出现未通过记录时，不能指定旧通过编号绕过。布局v2必须带 `--review`；布局v1不带参数仍可兼容执行并提示未绑定审核，不得据此认定内容通过。

## 处理“保留历史引用”的复核项

```powershell
node studio/bin/studio.mjs status --project projects/IP003_新故事 --json
node studio/bin/studio.mjs review-item --project projects/IP003_新故事 --item RI-状态返回的完整编号 --reason "保留旧版的实际理由" --evidence "实际核对的位置、内容及结论" --method ai --reviewer "实际审核者名称"
```

替换状态返回的完整复核编号，并填写实际理由、证据和审核者；`--method` 为 `ai` 或 `human`，理由与证据都必填。工具从该项取精确上下游版本和间接路径，只处理这一次变化。上游或路径再次变化会产生新项；要跟随新版时实际修改下游引用、保存并采用新版本，不用此命令假装已经改稿。

## 导出交接

```powershell
node studio/bin/studio.mjs export --project projects/IP003_新故事 --out deliveries/handoff/交接包1
node studio/bin/studio.mjs export --project projects/IP003_新故事 --episodes IP003-EP-001 --require-review --out deliveries/handoff/第一集交接包1
node studio/bin/studio.mjs export --project projects/IP003_新故事 --chapters IP003-CH-001 --out deliveries/handoff/所选章节漫改包1
```

`--out` 为v2项目 `deliveries/handoff/` 下的相对目录；v1仍用 `07_发布资产/`，目标必须不存在，且不能与工作资产目录相互包含。项目必须有已采用 CH、EP、SC、SHOT，且其依赖都曾采用。工具导出当前采用资产和完整依赖闭包，允许固定使用历史曾采用版本并提示复核，绝不从新工作稿偷偷补内容。

默认全项目导出；`--episodes` 和 `--chapters` 互斥，均接受逗号分隔的完整资产ID。按章节会选中使用这些章节的整集，可能带入同集其他章节。范围外内容作为必要来源证据进入包，不因此成为新增播放镜头。关联报告或提示词跨出所选制作范围时会警告，可拆分该资产或扩大范围；不要忽略警告而称完整交接。

`--require-review` 要求本次实际播放章节的每个版本具有精确快照的最新完整通过记录。v2始终启用；v1未传此选项时保留兼容方式并提示审核缺口。纯小说还没有EP、SC、SHOT时使用下面的 `resume`，不要虚构分镜来凑导出条件。

布局v2的菜单与CLI均执行完整审核约束，不能关闭；布局v1菜单默认要求审核，CLI需显式传 `--require-review`。两种入口共用检查实现，选择写入导出记录。

每个章节 ID 都需要对应分集，每个剧集 ID 需要场次，每个场次 ID 需要镜头。全新章节或场次没有下游时须补齐；同一 ID 的新版尚未重新桥接，但历史曾采用版已有完整制作链时，允许保留历史链导出并提示复核。包内新版资料不代表旧分镜已经跟随修改。当前播放时间轴不支持重叠镜头，叠化等方案仍按原技能手动交接，不能只改时间数字绕过实际冲突。

实际播放树仅使用当前采用镜头及其场次、剧集引用；历史镜头依赖保留在资产包中，不重复播放。`--json` 的导出结果带 `playback`，同 ID 新采用版尚未被当前镜头使用时会列入 `playback.uncovered_adopted_versions` 并返回 `warnings`。同一播放树不能混用同一剧集或场次的多个版本。

| 结果文件 | 用途 |
| --- | --- |
| `handoff.json` | 程序读取结构化交接 |
| `交接说明.md` | 人工阅读；可交给原 00、06—09 技能 |
| `来源与版本清单.json` | 核对实际使用 ID、版本与来源 |
| `内容审核记录.json` | 本次播放章节的真实审核记录；与结构成功分别看待 |
| `assets/` | 该交接使用的完整资产快照 |

## 生成小说阶段续作包

```powershell
node studio/bin/studio.mjs resume --project projects/IP003_新故事 --out deliveries/resume/续作包1
```

不要求先完成漫改。输出目录必须是v2 `deliveries/resume/` 下的新目录；v1仍用 `00_项目管理/`，不得与工作资产相互包含。包内有 `续作说明.md`、`续作信息.json` 和实际采用快照，包含设定、状态、章节、读取清单、工具待办和审核记录；未采用工作稿只列状态与问题，不混入采用正文。所打包快照的检查警告同时出现在命令 `warnings`、续作信息 JSON 及中文说明。

把续作包位置和本次目标交给新对话，要求实际读取其中的精确版本。若原项目后来继续变更，先重新查看状态再决定是否生成新包。每次使用新输出目录，旧包保留当时的交接记录。

## 失败与返回

失败信息应保留问题路径和原因；先修工作稿、引用或调用参数，再重新执行。不要因一次失败更改历史快照或伪造采用记录。已有项目、快照或导出目录不覆盖，改用合法的新编号或版本。

工具错误表示本地操作未完成，不代表故事审核失败；工具成功也不代表文学或成片质量通过。锁、事务与备份说明见[部署说明](部署说明.md)。

命令成功退出码为 `0`，检查未通过或操作异常为 `1`。JSON 返回至少带 `ok`；失败含 `errors`，检查可含 `warnings` 与 `stats`，采用或导出可含 `review_items`。中断事务成功恢复时返回 `recovered_transaction`。按这些显式字段判断，不能仅搜索输出中的“完成”二字。

## 布局迁移

从工作区根运行：

```powershell
node studio/bin/studio.mjs migration-preflight --project <旧项目目录> --to projects/IP003_新故事 --json
node studio/bin/studio.mjs migrate --project <旧项目目录> --to projects/IP003_新故事 --json
```

预检只读，迁移向不存在的目标目录复制并建立路径映射。ID、资产内容、版本、refs、历史快照及哈希保留，登记工作路径改为assets分区。异常结果和未完成迁移不能当成功；成功后以目标项目状态确认活动基准，旧源作为只读归档/回退材料，不形成两个同时写入的活动项目。详情见[重构实施说明](重构实施说明.md)。

## 链接审计与派生阅览报告

```powershell
node studio/bin/studio.mjs audit-links --project projects/IP003_新故事 --json
node studio/bin/studio.mjs render-report --project projects/IP003_新故事 --asset IP003-REPORT-001 --version 1.0.0 --out deliveries/views/报告1 --json
```

链接审计检查当前已采用REPORT的工作附件与对应冻结Markdown，分别报告原始路径失效、经精确依赖和迁移映射可解析，以及仍无法解析的链接；不扫描所有项目Markdown，也不改写冻结正文。派生报告必须输出到deliveries/views下不存在的新目录，包含阅读说明.md、view.json、reports派生Markdown和assets原字节快照。显式指定已保存版本时可阅览未采用REPORT，但不因此将它纳入正式交接或采用。输出只作阅读副本，不登记新资产、不替换采用基准、不回写快照，也不证明素材实际看检。未声明精确版本依赖或同ID多版本含糊时保留问题，不猜选最新文件。

`render-report` 返回 `root_issues`（选定根REPORT内的问题）及 `historical_issues`（递归引用的其他REPORT说明中的问题），每项包含 `asset_id`、`version`、`file`、一基 `line`、`raw_link`、`reason`、`scope: "root" | "historical"` 和 `issue_page`。两类问题都进入 `warnings` 与view.json；根问题非空时 `ok: false`，仅有递归说明问题时可返回 `ok: true` 并保留历史限制。致命结构、完整性或IO异常仍返回 `ok: false` 与 `errors`，不会降为历史警告。

未定位链接仅在派生Markdown改指 `link-issues/<问题ID>.md` 诊断页，标签附“未定位链接说明”；未定位图片改为普通诊断链接。诊断页不是素材，原文及原始链接完整保留于assets副本，不选择替代素材、不补造版本或依赖。单报告的 `issue_page` 相对输出视图目录；包顶层问题数组的路径相对包目录，包内报告自身记录的路径相对该报告视图目录。包派生视图按相同根/递归分类报告，阅读可用不意味着历史素材全部已定位或验收。

## 未采用候选停用与恢复

```powershell
node studio/bin/studio.mjs retire-asset --project projects/IP003_新故事 --asset IP003-MEDIA-002 --reason "本用途改用另一个候选，保留失败证据" --json
node studio/bin/studio.mjs restore-asset --project projects/IP003_新故事 --asset IP003-MEDIA-002 --reason "重新评估该候选用于另一个视图" --json
```

仅布局v2支持。任何曾采用过的资产，或被已采用下游引用的候选，均拒绝停用/恢复。工具在登记项保存lifecycle（active或retired，省略按active）并追加lifecycle_history；不改变采用指针、不删除文件或快照、不改来源/采用语义。status仍列出全部资产及retired列表，退役候选退出drafts和行动pending；继续保存/采用前先restore，恢复本身不表示审核或采用。

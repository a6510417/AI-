# 资产管理规范

## 工作室视觉基准与交付

制作入口遵循[工作室执行规则](工作室执行规则.md)，用[19视觉基准模板](../模板库/19_视觉基准与图片交付模板.md)对照真实采用版本、当前设计、逐文件职责及可用范围。文学角色的出处与旧外观建议不自动覆盖新视觉设计；参考从冻结MEDIA文件选取，工作稿和聊天记忆不作为新基准。

无真实SHOT的角色定妆词保存在MEDIA冻结附件或制作文稿，不为登记造SHOT/PROMPT。已有镜头的生产提示词遵循原绑定协议。视觉基准报告只组织所选基准，生产结果报告在依赖末端，不让媒体或提示词反向依赖含自身结果的报告。

清单由技能读取状态后对账，记观察时间、差异与未完成任务；工具没有自动同步自由文字。正式采用绑定准确版本的实际审核；可用性、观看范围、声音和成片证据分别交[11质检](../技能库/11_质量检查技能.md)。新表都是人读附件，不改变资产类型、历史快照或协议。

## 组成与责任

共享技能、模板和知识库提供创作规则；独立IP目录保存实际内容；当前 AI 通过 `studio/bin/studio.mjs` 调用本地命令检查结构及引用、冻结版本并导出。工具只使用Node.js内置功能，保留中文命令别名，无参数或 `--help` 仅显示帮助。用户通过对话交代任务，无需操作终端或菜单。工具不判断故事是否动人，也不自动执行技能或生成媒体。各阶段职责见[完整流程与交接](../使用说明/01_完整流程与交接.md)，参数见[接口规范](接口规范.md)。

工作稿、不可覆盖快照和采用指针分别管理：工作稿可编辑，快照用于追溯，采用指针决定生产基准。正式引用携带资产ID和版本，事件引用还包含所属章节；修改上游不会自动改写下游。

## 一个 IP 一个工作空间

用 `init` 建立 `projects/IP编号_项目名/`。新项目采用布局v2，登记资产在 `assets/<TYPE>/<ID>/`，输入在sources，制作文件在production，交接在deliveries。v1旧八目录按清单读取，不在活动项目旁保留第二个可写旧副本。具体故事材料属于该目录；共享技能、模板和知识库保留在根目录。不要从另一 IP 直接引用角色、地点或章节 ID；确需复用创作元素，应在获准的当前项目建立新资产并保留真实来源说明。

现行 `projects/` 不附带教学故事，新 IP 用 `init` 自建。已有项目的旧编号可保留为别名，正式依赖使用IP资产ID；纯文字独立任务仍可沿用原编号。地点 LOC 是可复用空间，SC 是某一叙事时段的场次，EP 是剧集，三者不能混用。字段和目录详见[数据协议](数据协议.md)。

## 从工作稿到采用基准

重要视觉元素的设计、保存、审核、确认范围和采用锁定是不同事实。候选设计保存为准确版本；真实审核绑定其快照；按授权正式采用后才作为当前生产基准。新版采用只改变指针，旧版及其下游精确引用保留。`visual_base.locked` 只控制编译时不重新设计，不代替这条生命周期。

服装、饰物、武器等长期组件使用现有PROP独立编号；人物CHAR引用组件，技能／特效机制由WORLD承载，镜头变化由STATE承载，实际图像由MEDIA承载。登记名称、归属、参考、材质、配色、识别点及允许变化等用实际内容，不为填齐字段编造尺寸或首次出场。填写见[19视觉基准模板](../模板库/19_视觉基准与图片交付模板.md)，执行字段只见数据协议。当前采用、曾采用但被新版替代、未采用候选按真实记录推导；不要把这些混入原有来源枚举或active/retired。

以下步骤由当前 AI 执行：

1. 用新建资产工具生成并登记所需类型骨架，按技能和模板填写实际内容。每章七个交付文件和元数据一起整理。
2. 运行检查，修复结构、编号和引用错误。草稿内容未完整时保持建议或待核实，不伪装成审核通过。
3. 运行保存版本，形成不可覆盖快照。首次保存可通过工作目录自动登记。
4. 内容审核核对设定、人物知情、因果、道具和来源，登记真实范围、结论及证据并绑定已保存快照。需要修改时回到工作稿，用新版本号保存并重新审核。
5. 在已获授权范围内采用明确版本并绑定审核记录，依赖必须曾经采用。依赖先于下游保存与采用，不构造循环；旧布局项目未绑定审核的操作不能当作内容通过。

审核是独立冻结记录，绑定具体快照的校验值。状态视图区分工作稿、采用版和工具待办；采用和正式交接可要求精确版本的完整通过记录。AI审核与用户实际审阅分别记录。

版本号使用三段数字。建议文字修正增加末位、实质内容修订增加中位、整体重构增加首位；工具验证格式和不可重复，不代替创作者判断变化大小。已经存在的快照不覆盖，哪怕只是标点修改也要换版本号。

## 连续性与新增设定

角色档案记录长期动机、关系和固定特征；状态资产记录事件带来的变化。角色知道的事实、读者已知信息和作者幕后设定分别保留。道具按获得、转交、失去的事件追踪，不能在切镜或下一章自动归位。

新增世界规则、能力和关系作为候选设定列在章节包中。采用之后再修订对应设定资产；正文不能悄悄覆盖世界基准。状态变化指向明确事件、故事时间与生效节点，倒叙按当时状态读取。

## 上游变更后的复核

采用上游新版本会列出直接及间接下游复核提示。逐项决定：下游需要跟随新版时，实际修改其引用和内容后保存、采用；需要保留旧时段或旧创作分支时，可以继续固定引用曾采用旧版，写明内容依据。

提示不代表下游已经修好，也不意味着工具应自动追新。确认旧版仍适用时，使用 `review-item` 记录状态返回的精确复核编号、实际理由、证据和审核者。它只处理当前版本组合，上游或依赖路径再次改变会重新提示。不要手工清空记录或改历史快照。已生成媒体即使文字已修正仍要另行复查。

## 导出、备份与恢复

漫改包冻结实际使用的资产及版本，可以按已完成剧集或相关章节选择。核对所选 CH、EP、SC、SHOT 完整链路，缺少分集或镜头时补实际创作，不用空 JSON 通过检查。正式交接启用完整审核约束，未采用秘密或新结局不能混入采用正文。

包内完整依赖与实际播放树分开。因提示词引用而保留的历史镜头不重复参与播放；当前采用镜头决定具体剧集、场次和章节版本。未被使用的新采用版会明确提示。JSON和中文说明由同一批版本生成，供程序与创作者分别读取。

只有小说时生成 `resume` 续作包，无需强行补桥接。换对话先读续作清单和精确版本，再核对原项目是否继续变更。状态中的工具待办与报告里的真实制作任务分别判断。

实际参考图、声音或视频放在各自MEDIA资产内部，登记 `data.files` 后检查存在性、路径与哈希；不要登记一个不存在的 `file_path` 就称素材齐备。导出会带实际文件，画面和声音是否可用仍须打开检查。

PROMPT的可选 `reference_bindings` 进一步检查MEDIA确切快照中的具体文件；可选 `usage_id`／`expected_usage_id` 用途匹配按[数据协议](数据协议.md)维护，不从新工作稿选图。每集REPORT可附生成返修台账、失败证据和剪辑交接；正式引用列随包基准与采用结果，其余候选文本定位。REPORT位于依赖末端，MEDIA不反向引用含自身结果的报告。台账新增内容保存新版本，旧失败记录和历史附件保留。

备份时复制完整 IP 目录，包括隐藏的 `.ip-system`、`project.json` 与工作稿；仅复制正文无法恢复采用历史。复制前结束该项目的写操作。移动完整根目录后使用新路径打开，不修改资产 ID。

锁和中断由工具进行可验证恢复。活动锁被拒绝时先检查是否有另一个进程或会话正在操作；无法识别的锁或完整性失败保留现场，按[部署说明](部署说明.md)诊断。不要删除历史或覆盖哈希来“修复”错误。

写操作按项目加锁，先准备完整内容并校验，再提交目录与清单；中断的临时内容不能成为已采用版本。工具拒绝越界路径和跨IP引用，提交前核对清单是否被外部改动。此机制保护本地单项目操作，不承担共享网络目录的多人数据库职责。

资产停用、恢复、迁移与派生报告的具体行为见[重构实施说明](重构实施说明.md)，不会改写文学来源、冻结历史或既有版本引用。未来接入媒体或协作服务时继续沿用ID、版本和来源追溯。

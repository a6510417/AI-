# 部署与日常运行

## 运行条件与入口

使用Node.js 22或更新版本，工具只使用内置功能。共享资源在工作区根的 `studio/`，活动项目在 `projects/`；保持这两部分及 `.agents/skills/`、`AGENTS.md` 一起可用。手动阅读技能不依赖Node.js。

用户通过对话交代任务。当前 AI 在工作区根目录调用工具，以下两种调用均仅显示帮助：

```powershell
node studio/bin/studio.mjs
node studio/bin/studio.mjs --help
```

工具不提供交互菜单，用户无需双击启动文件或操作终端。AI 可调用的命令见[接口规范](接口规范.md)，首次创作见[首章实操](../使用说明/03_从空项目到首章实操.md)。工作室管理与制作命令统一使用 `studio/bin/studio.mjs`，保留中文命令别名；新项目采用当前工作室目录布局。完整迁移与回退材料位置从[README](../../README.md)及[重构实施说明](重构实施说明.md)确认。

## 日常顺序

当前 AI 先查看状态和所需冻结版本，再完成工作稿，检查、保存、真实审核、绑定审核采用，最后生成小说续作包或所选剧集交接。新版本不覆盖已有快照，上游变更不自动追新下游引用。v2采用强制审核绑定，漫改导出强制播放章节审核；MEDIA、音频和成片仍需实际视听检查。

完整备份包含project.json、工作文件及隐藏.ip-system。备份前停止写入；切换机器不要只复制正文。恢复先核验新副本，保留故障现场；使用不同输出目录保留各次交接证据。

## 中断与故障诊断

| 现象 | 处理 |
| --- | --- |
| 项目被占用 | 确认原进程是否仍运行；等操作结束，不并发编辑清单 |
| 写操作中断 | 先读状态/检查，用 `recover --project <项目目录> --json` 纯恢复，再读状态并核对原登记与输出；不以重复新建、保存或导出代替恢复 |
| 恢复已完成但后续请求失败 | 保留 `recovered_transaction`、`recovered_lock` 和原错误；先确认原成果，不直接递增版本或重复业务操作 |
| 恢复声明的进程再次中断 | 仅纯恢复入口在同机原进程和恢复进程明确退出、旧锁未变时追加唯一接替声明；旧声明保留，不手工删锁 |
| 无法识别、异机或无法验证的锁或恢复声明 | 保留现场和错误，核对归属；工具拒绝接替，不猜测解除 |
| 阅读视图已生成但根链接未通过 | 阅读实际输出及诊断页，处理 `root_issues`；检查失败不表示没有产物 |
| 项目清单外部变更 | 核对两份证据，协调手工编辑，拒绝覆盖其他会话结果 |
| 历史哈希失败 | 停止采用/导出，调查或从完整备份恢复，不重算哈希掩盖错误 |
| 路径、引用、章节资料失败 | 根据错误修工作稿，再检查并保存新版本 |
| 导出缺制作链 | 按17完成真实EP/SC/SHOT，不用空壳凑链路 |
| 迁移未完成或目标已存在 | 保留旧源和迁移产物，按预检报告处理，禁止覆盖/猜测完成 |

本地锁只保护单项目工具写操作，手工文件编辑仍需明确归属。迁移、停用和恢复会改变项目管理状态，不改变冻结历史或来源语义。

纯恢复使用现有路径、哈希和提交校验；无待恢复事务时成功但不制造业务操作。接替声明按旧锁 token 和前恢复 token 唯一生成，独占创建后再次核对锁；两个恢复者不能解除后来取得的新锁。若声明损坏、循环、token 不符或进程存活状态未知，保留现场并从已核验的完整备份副本排查，不修改故障历史或重算哈希。无法安全自动恢复的现场仍需维护者核对，不能把反复重试写成已修复。

## 维护者验证

维护时由 AI 在工作区根运行既有及新增测试，以实际文件为准：

```powershell
node --test studio/tests/*.test.mjs
```

文档修改先核对链接、唯一模板和任务范围；工具/布局修改运行相关测试和完整回归。验证记录在[更新日志](更新日志.md)，不预填通过数量。结构回归、技能行为、媒体检验分别记录，临时试验不写入正式故事。

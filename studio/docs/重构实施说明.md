# 重构实施说明

本文件说明当前目录、工具行为和兼容边界，不作为测试通过记录。实际迁移、验收与发行证据从[工作区README](../../README.md)和[更新日志](更新日志.md)进入；历史报告保留当时事实。命令参数统一见[接口规范](接口规范.md)。

## 1. 目录与规则的唯一来源

| 工作区位置 | 内容和维护边界 |
| --- | --- |
| studio/ | 当前工具、规范、创作手册、唯一模板和知识参考 |
| projects/IP编号_项目名/ | 活动故事及实际资产，不混教学演练 |
| .agents/skills/ 与 AGENTS.md | 九个任务入口、最小读取路线与工作区规则 |

工作室执行规则管权限、采用基准、媒体证据和交接；AI执行规范管来源和状态表述；数据协议管机器字段；接口规范管命令。阶段手册保留方法、必交项与裁剪条件，填写骨架在模板库维护。03角色、04一致性、05场景、07分镜、09提示词、10适配、11质检手册链接对应唯一模板，不再维护内嵌副本；完整包和单图/单镜/编辑明确分支。

## 2. 布局v2与内容v1分别管理

`project.json.schema_version: 2` 选择新布局：

```text
projects/IP编号_项目名/
  项目入口.md
  project.json
  assets/<TYPE>/<资产ID>/asset.json 与正文/附件
  sources/来源索引.md 与原稿/原始参考
  production/审核输入、制作文件及历史工作记录
  deliveries/handoff/ 新漫改交接包
  deliveries/resume/ 小说续作包
  deliveries/export/ 迁移保留的历史导出
  deliveries/views/ 可移植报告阅读副本
  .ip-system/ 原冻结历史、审核、事务、迁移与管理记录
```

资产内容仍是 `asset.json.schema_version: 1`，13类型、来源/采用枚举、ID、版本、refs、事件引用、七文件章节包及MEDIA清单保持原协议。工作路径由project.json登记，来源索引和入口是人读导航，不能取代采用指针或自行建立机器依赖。

唯一命令入口为 `node studio/bin/studio.mjs`。命令行、中文菜单与Node公开函数 `initProject` 均默认创建布局v2；需要建立旧布局验证夹具时显式传 `--schema 1` 或 `schemaVersion: 1`。v1历史项目按原八目录和输出约束读取；不在同一活动项目同时建设v1和v2工作资产。

v2采用必须带精确完整通过的 `--review`；漫改export强制检查实际播放章节的最新完整通过审核，不能关闭。v1维持旧参数兼容并明确提示审核缺口。两者都不把文字审核、文件存在或章节门禁当图片、声音或成片视听验收。

## 3. 复制迁移、校验与回退

先用migration-preflight读取源项目和目标规划，检查项目结构、冻结历史及路径映射；再用migrate向不存在的目标项目复制。失败、不完整迁移标记、锁或完整性问题不得视为成功。已有目标拒绝覆盖，源项目和迁移产物保留供诊断。

迁移将登记工作资产放assets/TYPE/ID，明确原稿放sources，未登记制作记录和脚本放production；既有续作与导出分别迁入deliveries/resume和deliveries/export。资产字节、ID、版本、refs、快照文件、manifest哈希、采用/审核/复核历史保持；原resumes、exports、operations字段不重写。

工具在 `.ip-system/migrations/<迁移ID>/migration.json` 保存源/目标、源清单校验值、每文件旧新位置与哈希、prefix_mappings及complete/incomplete状态。历史记录中的旧路径通过已完成映射解析；冻结报告正文不为修路径改写。

迁移完成后对目标运行status、validate与按需audit-links，核对基准与未完成事项。只有一个目录继续作为活动写入位置；旧源归只读archive或完整备份。需要回退时先停止目标写入，保留目标新增工作，再从完整备份恢复一个独立副本并核验，不覆盖或重算历史哈希。具体旧源/备份位置从当前README与实际迁移记录取得，不从历史教程猜选。

## 4. 候选生命周期与报告阅览

retire-asset和restore-asset只处理v2未曾采用、未被已采用下游引用的候选。登记项lifecycle为active/retired（缺省active），工具追加lifecycle_history。文件、快照与审核保留；status全列但退役候选退出drafts和行动pending，保存/采用前需恢复。恢复不会采用，也不会关闭内容问题。已采用资产的替换继续保存、审核、采用新版本，不用候选退役绕过依赖。

audit-links只审计当前已采用REPORT的冻结Markdown及相应工作附件，原路径是否存在与精确版本能否解析分别报告。普通附件里的ID不会自动形成依赖；报告引用不完整或同ID多版本不唯一时不猜最新文件。全工作区共享文档链接检查属于维护验证，不由此命令替代。

render-report以精确已保存REPORT生成deliveries/views下的新目录；显式版本允许未采用报告阅览。assets副本保留冻结原字节，reports是重定位链接的派生Markdown，阅读说明.md和view.json标明来源版本、哈希与未解决项。新交接/续作包可携带同类派生阅读视图，原冻结资产不变。派生视图不登记新资产、不会改变refs或采用指针，也不代表媒体已看检。

阅读视图区分本次选定根REPORT的 `root_issues` 与递归引用说明的 `historical_issues`；后者指其他精确REPORT版本中的问题，不代表历史素材已定位。两类问题都保留在 `warnings` 和视图记录中。单独 `render-report` 在根问题非空或发生结构、完整性、IO等致命异常时返回 `ok: false`；只有递归说明问题时可以交付当前阅读视图，并明确保留历史限制。包的派生视图结果采用相同分类，不能由视图可阅读推定整包所有素材无问题。

无法定位的链接在派生Markdown中指向 `link-issues/<问题ID>.md`，标注“未定位链接说明”；原图片链接改为普通可点击的诊断链接，不伪装成图片。问题页列确切REPORT版本、文件、一基行号、原始链接和原因，素材状态仍为未定位，不提供替代文件或猜测版本。原冻结正文与原始链接保留在assets副本及原快照中。`issue_page` 在单报告结果中相对阅读视图目录，在包顶层结果中相对包目录；包内各报告的内部记录仍相对该报告视图目录。

## 5. 维护与验证

按[部署说明](部署说明.md)运行工具/布局相关检查及完整回归；用真实最小任务验证九个入口的最小读取、单图不扩包、完整交付不丢项。检查共享Markdown本地链接、SKILL元数据、模板唯一来源与历史导航；迁移另核对原始文件清单和哈希，候选生命周期另核对保留文件及待办变化。

维护只处理当前资源与获授权项目，不把历史记录更新为当前事实，不改个人配置。测试结果、实际媒体检查和用户人工意见分别留证据；本说明不预填通过数量或已完成迁移结论。

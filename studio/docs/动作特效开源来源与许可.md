## 三、明确未引入的规则

| 上游内容或候选 | 未引入原因及项目替代 |
| --- | --- |
| Fight Prompt Director 的极速档动作数、镜头数、0.15 秒起手；Higgsfield 每 5 秒 1–2 节拍等 | 不同模型/语境经验互有冲突。改为按时长、接触次数、参与者与镜头变化决定密度，失败时拆完整事件 |
| 每次固定输出三套强度、默认 15 秒与 16:9 | 用户与项目已有交付格式优先，不增加无用版本 |
| 用模糊 fighting energy 统一替代具体武打；动作场景一律不用元素绑定 | 会损失可读因果，且泛化了平台行为。改为简化动作链、调整参考职责与机位 |
| UE5 配方默认 HUD、血条、固定剪辑数量；实拍模板禁止 3D/CGI | 不适用漫剧画风。游戏 UI 需有明确需求，三维不能继承反三维否定词 |
| 所有生物必须粗糙不对称、所有特效必须接触阴影 | 破坏既有造型或能量材质。按实体、透明/发光特性及世界设定选择相互作用 |
| 所有模型英文更好、前 30–40% token 必然更重要、模型普遍能准确模拟物理 | 本次未获得足以支持这些通用结论的证据，不进入硬规则 |
| 只要加 UE5/Lumen/Nanite/Niagara 就等于真实使用引擎 | AI 提示不能替代引擎工程、参数或实测。只把目标观感写进提示 |
| 固定分辨率、API 模式、素材数量、参考标签和特效预设 | 与实际入口相关，不能从 Higgsfield 推断即梦网页/App。使用前核实当前能力 |
| 指定模型/API、默认上传、持续付费重抽、引入账号及插件 | 本任务为技能与提示词补全，不引入新的执行依赖；生成仍按用户授权范围进行 |
| 靠改词绕过安全过滤的教程 | 不属于提示质量补全，不纳入工作流 |

| fal-ai-community/skills | 有可读摄影 skill，README 声明 MIT，但当次根目录未读到 LICENSE；执行又绑定 genmedia/fal，本次无需引入 |

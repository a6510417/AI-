# 内容审核模板

用途：审查策划、章纲、小说七文件、漫改分集分场剧本和连续性，形成有证据的问题、实际修订与复核记录。对应 [16_内容审核技能](../技能库/16_内容审核技能.md)。镜头、提示词及实际媒体质量使用原 [07_质量检查模板](07_质量检查模板.md)。

## 一、范围与依据

- IP、审核记录资产、记录版本：〔待填〕
- 被审资产 ID、版本与具体范围：〔待填：全章／局部／仅摘要〕
- 实际读取的文件、采用设定和前后章状态：〔待填：ID＋版本；未取得部分列明〕
- 本次检查方式、修改权限和停止阶段：〔待填：忠实整理／正常改编分别判断；明确须保护的决定性结果、关系及能力功能时点，已授权重设计的事故／动作／转场等不逐项求确认〕
- 阅读模式、来源及是否硬性：〔待填：追读向／短剧口播／氛围短篇；用户要求或工作假设。未记录时写“审核时推断”，不假装策划已采用〕
- 本轮内容目标及判断依据：〔待填：用户留住观众／展示制作水平等要求、明确硬约束、选用建议、创作者自行选择分别记录；采用状态不是质量证据〕
- 初读稿件所得与后续核查：〔待填：先按用户目标读稿及必要来源所得的位置证据；作者解释／自检后实际补查了什么，无则写无，不照抄其通过结论〕
- 尚未检查的文本／媒体与原因：〔待填〕

## 二、逐项结论

| 检查项 | 通过／需修订／待核实／不适用 | 具体证据、位置与限制 |
| --- | --- | --- |
| 来源与连续性 | 〔待填〕 | 〔待填：原文／授权改编分明，本轮保护的结果、动机关系及能力时点不冲突，重设计局部因果与本版状态自洽；道具伤势、七文件、伏笔揭示及必要前后文〕 |
| 人物与叙事取舍 | 〔待填〕 | 〔待填：人物目标、策略、选择与微反应符合当时人设；核心行动与兑现，背景／回忆／面板／奖励当场作用；压缩是否保留剧情功能〕 |
| 观看／阅读节奏 | 〔待填〕 | 〔待填：连续开头的实际范围、行动如何让压力增长或变化并迫使选择、追问推进与兑现、重复确认；按实际模式使用R/D编号，不只检查第一句钩子〕 |
| 视觉表达 | 〔待填〕 | 〔待填：25视觉机会取舍、低文字权重事件、可见爽点和反应、环境叙事与伏笔、高潮与转场；扩写不必全选，删除保留功能依据；手机端可读〕 |
| 制作可行性 | 〔待填〕 | 〔待填：正常表演、动作因果／空间／道具交接、时间及场面负担；只做文字时不冒称镜头或媒体验收〕 |

五个面向分别判断，来源通过不能抵消节奏或视觉表达失败。完整阅读、哈希、少字、功能齐全和合计时长各有用途，不能单独证明好看。用户内容目标未达记应修订，未解决时整体须需修订；个人偏好或不妨碍目标的细节才记可选润色。

原稿与改编不同须说明，不自动记为错误。事故合理化、局部攻防、对白和转场在已有权限内重设计时，核对自洽与受保护结果；一次性魂穿的魂影、电弧或空间效果，须区分过程表现和新增可重复能力。忠实整理才按原句原动作约束。旧IP稿自行选的弱特效或保守表达不是通用禁令。

意识授艺中的能量金人等主观教学表现，与现实召唤、代打或高阶技能分开核对；不凭效果名称判越界。记录展示如何承接学习与实战、是否留够正常观察时间、是否保持外界压力。

## 七、结构化审核输入与绑定（使用本地审核门禁时填写）

由执行审核的 AI 根据真实阅读结果生成输入文件。此表提供填写口径，精确 JSON 字段以数据协议为准；不要把带占位的模板作为已完成审核直接登记。

| 字段 | 应填内容 |
| --- | --- |
| 被审对象 | 〔待填：已保存资产 ID、版本；快照校验值由工具读取绑定〕 |
| `method`／`reviewer` | 〔待填：`ai` 或 `human`、实际审查者；AI 与人工分别记，不凭空填人工〕 |
| `scope` | 〔待填：实际读取的正文、配套资料、前后章与设定范围〕 |
| `coverage` | 〔待填：`full` 全范围／`partial` 局部；省略默认局部〕 |
| `result` | 〔待填：`pass`／`revise`／`unverified`，与问题处理状态一致〕 |
| `issues` | 〔待填：无问题为 `[]`；每项含 `id`、`severity`、`status`、`description`、`evidence`〕 |
| `evidence` | 〔待填：本轮阅读的位置及支持结论的内容；不能仅写工具校验通过〕 |
| `reviewed_at`（可选） | 〔待填：实际已知的带时区审核时间；未知可省略，录入时间由工具记〕 |

问题程度映射：阻塞交接 → `blocker`，应修订 → `revision`，可选润色 → `suggestion`。处理状态映射：待处理、已交修改稿、已实际应用待复查均为 `open`；实际复查通过才为 `resolved`。开放的阻塞／应修订问题不能配整体 `pass`。

- `record-review` 实际返回的审核 ID：〔待填：执行成功后登记，不能预造〕
- 对应采用操作及审核 ID 绑定：〔待填：精确版本；未绑定则说明采用不代表审核放行〕
- 发布交接是否启用 `--require-review`：〔待填：启用时需 full＋pass，且无 open blocker／revision〕
- 后续修订需重新审核的版本：〔待填：不能把旧版本通过记录复制给新版〕
- 较新审核与旧通过记录的冲突：〔待填：不能选择旧通过记录绕过新问题〕

# 19_视觉基准与图片交付模板

用于角色／场景图片生产、跨次复用和向视频任务交付。承接[03角色资产设计](../技能库/03_角色资产设计技能.md)、[04角色一致性](../技能库/04_角色一致性管理技能.md)、[10模型适配](../技能库/10_模型适配技能.md)和[11质量检查](../技能库/11_质量检查技能.md)。实际尝试与失败链用[17台账](17_生成与返修台账模板.md)，本模板不替代生成记录。

按任务选用下面三段；单图可合并重复说明，不强制补三视图、额外参考图或执行生图。项目权限、状态读取和采用步骤见[工作室执行规则](../docs/工作室执行规则.md)及[AI执行规范](../docs/AI执行规范.md)。尖括号／待填说明须替换，未执行项如实写未执行。

## 一、当前视觉基准

- 项目、本次目标与适用范围：〔待填：角色／地点、章节时期或镜头；只列本轮需要的基准〕

- 采用设计与文学来源的关系：〔待填：身份／剧情来自哪些 CHAR、LOC、CH；哪些外观来自参考观察或原创设计，旧视觉建议有哪些未继承；不修改文学档案或历史〕
- 本次画风与比较依据：〔待填：已采用造型、材质、色彩与光照表达及实际参考；没有风格图不假称已绑定，也不只堆UE5等标签〕

### 固定组件与多角度延展（按需）

- 本次组件选择：〔待填：身份／服装／道具／武器／技能表现职责、实际 CHAR／PROP／WORLD 精确版本及参考文件；已锁版本沿用，其表情、持物、湿污和伤损另按STATE节点；不为每次生成重设计〕
- 设计选择与元素预算：〔待填：本图主要辨识点、次级轮廓／配色、关键组件和辅助质感；装饰与手机端识读、动作的取舍，引用现有设计理由即可〕
- Face Geometry Lock：〔待填：实际确认 MEDIA ID＋版本＋文件＋视角及确认依据；新增角度从共同几何延展，哪些结构不可唯一反推；没有图或未确认时保留文字候选／待确认〕
- 固化与生命周期证据：〔待填：实际保存、精确审核、采用和本版锁定分别记录；新版对直接引用者的影响，不新建注册库或抹旧版本〕

固定描述与剧情动态状态分开提交。来自未来技能、后期武器或一次性魂穿的特效不加入角色永久外观；独立定妆不兼作道具细节、技能展示与剧情百科。

- 已知资料差异与影响：〔待填：正文与出场清单、来源标签、旧视觉建议等差异的位置、受影响用途及下一动作；授权保存时进入REPORT后续事项，不默改历史〕

## 三、图片交付预检

| 检查项 | 实际对象、方式与证据 | 本用途结论及待办 |
| --- | --- | --- |
| 精确文件与来源 | 〔待填：选用冻结版本、相对文件、已有用途标识与正文来源；文件校验不等于看图〕 | 〔待填：通过／需修订／待核实／未检查／不适用〕 |
| 剧情依据与最终稿覆盖 | 〔待填：对照上表的相关正文／采用事件、当前时点、最终实际提示词与实图；新增剧情有出处或授权，补全不冒称原文〕 | 〔待填：区分提取错误、补全越界、提交漏项与生成未遵循；关键剧情错误阻塞相应用途〕 |
| 真实格式、尺寸与背景 | 〔待填：实际可打开、格式与尺寸、目标／实际画幅；透明性须有通道证据，未知不猜〕 | 〔待填：不拉伸人物；无固定像素要求时不强制转换〕 |
| 身份与造型 | 〔待填：对照本次设计版，核对年龄表现、脸发、体型、服装、饰物、标记及自身左右〕 | 〔待填：遮挡／取景外明确列未见，不能当成符合〕 |
| 几何与组件复用（按需） | 〔待填：对照实际确认视角的共同眉眼、鼻唇、颧颊和下颌；固定服装／配饰的精确版、袖口边界及装饰预算；近景只查可见部分〕 | 〔待填：各角度单独美化、组件替换与正常透视分开；静态复杂度风险不等于已发生视频漂移〕 |
| 人数、持物与故事状态 | 〔待填：单一时刻的姿态、持有人、数量、场地状态和禁见信息；首帧不能提前完成动作〕 | 〔待填：已证实硬错误阻塞相关用途，不以漂亮画面抵消〕 |
| 取景与可见空间 | 〔待填：本用途要求的脸、手、发顶、鞋底、关键道具、动作空间与留白；不强迫每图全身〕 | 〔待填：可见范围支持哪些用途；关键条件不可辨时保持待核实〕 |
| 画风与参考职责 | 〔待填：造型、材质、光源和基础色是否相容；人物纯底图不自动承担剧情环境〕 | 〔待填：光照变化不等于换装或基础色改设〕 |
| 编辑及跨图复查（按需） | 〔待填：原图→返修图、问题处、保留集、邻区和共同受影响角色／道具；比对实际文件〕 | 〔待填：仅交返修文字不关闭媒体问题〕 |
| 目标入口接收 | 〔待填：所选入口实际接受的格式与输入职责；公开文档、当前界面、上传结果分开〕 | 〔待填：未操作写未核验，不预编引用标签或承诺视频稳定〕 |

- 可交付的精确文件与用途：〔待填：哪些版本与文件可作人物参考、首帧或其他用途；不笼统写全包合格〕
- 已接受取舍及依据：〔待填：真实授权、受影响用途与剩余限制；无则写无，不记为原条件下修复〕
- 仍阻塞／待核实事项：〔待填：具体位置、影响用途、最小处理与完成所需证据〕
- 交下一阶段的材料：〔待填：独立正文、选用文件与职责、实际设置／未知项、需要的视频声画验证〕

需要正式保存时沿用 REPORT 及精确 MEDIA 引用；必需随包的版本放 REPORT 的 `refs`／`data`，附件里的编号不会被工具自动解析为依赖。REPORT 汇总结果，MEDIA／PROMPT 不反引含自身结果的报告。正式 PROMPT 必须关联真实 SHOT；没有分镜的图片任务保留真实文字附件，已有采用图的提示词从 MEDIA 冻结附件定位，不造 SHOT／PROMPT。结构仍以[数据协议](../docs/数据协议.md)为准，不新增资产类型或必填机器字段。

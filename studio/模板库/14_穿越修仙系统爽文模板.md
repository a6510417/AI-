# 穿越修仙系统爽文模板

用途：为已明确选择“现代人穿越＋修仙世界＋系统奖励”组合或明确选用本模板的项目提供可选章节骨架。单独出现穿越、修仙、系统或升级标签不启用整套机制。对应 [13_创意策划技能](../技能库/13_创意策划技能.md)、[14_剧情规划技能](../技能库/14_剧情规划技能.md) 和 [15_小说生产技能](../技能库/15_小说生产技能.md)。

本模板是结构，不是某一本书的续写。可以借鉴常见修仙类型元素，包括通行境界名、门派组织、功法类别、试炼和打脸结构；用户明确要求沿用某部作品的人物或设定时，按该要求处理并标明是指定借鉴，不伪称原创。不整段、整章或连续台词照搬现成小说，也不把参考材料里的专有人名、专属门派、独特功法和原句写进本模板。阅读模式建议追读向，主引擎可用公开规则翻盘，也可按项目选择期限压迫、信息差或身份欠账。下列机制、节奏、播报和内容尺度是建议；只有用户要求或项目明确采用的条件才成为验收约束，不覆盖既有世界规则、人物设定和内容边界。

## 一、可选的三条公开规则

以下是一套机制示例，按当前故事选择、修改或省略；未选定的奖励、回收和积分不能自动写入世界。选用的规则应交代触发、代价和结果。系统可按已采用机制提供结算、任务或其他提示，提示与事实、角色选择分别表达。

| 规则 | 读者能看见什么 | 每次使用的代价 | 不能做什么 |
| --- | --- | --- | --- |
| 成长节点 | 境界或阶段提升后，打开一次奖励 | 奖励随机，不按主角愿望给 | 不连续开包，不跳过境界 |
| 资源回收 | 用不到的功法、丹药、法宝变成对应精华 | 原物消失，精华不能直接提升人物境界 | 不回收别人正在使用、来源未交代的物品 |
| 公开兑现 | 当众完成一件具体的事，获得可计数的积分 | 失败、逃跑或被揭穿会扣分或暴露 | 不把口头嘲讽算作成功 |

只有项目实际需要且获准创作的境界、货币和积分才设计名称与规则，先在 WORLD 工作稿中记录；正式采用时先保存快照，再审核该确切版本并采用。用户要求通行境界体系时可以沿用并记录来源；模板不把“十境十层”写成唯一体系。

## 二、单章五拍

五拍适合集中兑现一件事的章节，可按本章作用增减、合并或换序；过渡、关系和收束章不必安排公开打脸或新奖励。字数按本章任务定，不按固定字数凑。

| 拍 | 可用写法 | 常见风险 |
| --- | --- | --- |
| 1. 当众压力 | 谁在场，主角缺什么，对手凭什么压他 | 大段解释世界观 |
| 2. 错误判断 | 对手或围观者根据旧信息下结论 | 主角内心预告自己会赢 |
| 3. 一次使用规则 | 主角主动消耗一次奖励、精华或积分 | 连续弹出新功能 |
| 4. 可见结果 | 一个动作造成一个结果，围观者改口 | 只写“全场震惊” |
| 5. 新缺口 | 留下具体的人、期限、物品或追兵 | “真正的挑战才刚开始” |

需要追读钩子时，可用未完成动作、明确时限或刚发生的反转；下一章承接已有状态。新奖励是否出现取决于已采用规则与本章任务。

## 三、升级循环

仅在项目选用对应机制时，可参考以下循环，不为凑循环新增功能：

1. 先给一个主角暂时打不过的对手或过不去的门槛。
2. 奖励提供新办法，但保留限制：次数、持续时间、使用范围或材料。
3. 主角用这一个办法解决眼前的事，并付出规则里写明的代价。
4. 对手、师门或朝廷据此调整；下一次不能用同一个信息差重复打脸。
5. 多余资源进入回收，只能增强已有功法或器物，不能直接购买境界。

建议约三章检查一次压力来源是否重复，可轮换境界门槛、资源短缺、身份暴露、门派任务、追兵期限或他人欠账；持续同一冲突但有实际进展时可以保留，不为换来源破坏因果。

## 四、关系欠账

故事需要关系欠账时，写清一笔具体未完成事项，使用 PLOT 现有的 `relationship_debts`：

| who | owes | what | 什么时候必须处理 |
| --- | --- | --- | --- |
| 〔人物〕 | 〔人物〕 | 〔一件具体的事，不是“亏欠”〕 | 〔章节或事件〕 |

师门、朝廷、家族和同伴对主角的看法要随事件改变。受过帮助的人不能每章重新害怕一次；被打败的人不能无原因消失。

## 五、系统提示写法

建议提示独立成行并集中表达一件事；本项目若采用其他播报风格则沿用。以下是结算提示示例，不限制已有系统的任务、预告或查询功能：

```text
【条件】已经发生的行为或境界变化。
【结果】得到的一个物品、权限或积分。
【限制】次数、持续时间、范围或不能提升的内容。
【消耗】本次实际扣掉的资源；没有则写“无”。
```

建议减少“叮、恭喜宿主、装逼成功”这类套话，以具体信息服务叙事；项目已采用的提示语气可以保留。提示中的评价与客观结果分开，不把角色尚无依据知道的后续剧情提前泄漏给角色。角色知道、读者知道和作者知道仍然分开。

## 六、项目落盘

| 内容 | 写入 |
| --- | --- |
| 项目实际采用的穿越身份、境界与系统规则 | WORLD |
| 主角、对手、知情范围和关系 | CHAR |
| 门派、城镇、试炼场 | LOC |
| 技能／功法机制与长期特效表现 | WORLD的相应基准，状态变化由STATE记录；视觉表现与能力功能分开 |
| 反复使用的实体器物、武器、凭证 | PROP |
| 阅读模式、主引擎、关系欠账、章纲 | PLOT |
| 每章实际变化 | CH 七文件 |
| 项目实际存在的境界、持物、知情、积分和伏笔变化 | STATE |

新出现的系统功能先列入章节“新增设定”；候选工作稿可先预审，正式版本先保存 WORLD 快照，再审核该确切版本并按既有授权采用，操作见 [接口规范](../docs/接口规范.md)。正文不能把没采用的新功能写成既有规则。

## 七、开写前核对

- 读者能否用一句话复述本章主角做成了什么，以及为此失去了什么。
- 奖励是否在使用前就有来源，而不是危险出现后临时生成。
- 围观者的反应是否对应他们刚看见的事实。
- 章末是否留下具体的人、物或时间，而不是情绪口号。
- 本章有没有依赖上章已经改变的境界、伤势、物品和知情；不能切章自动恢复。

## 八、内容尺度建议

内容尺度遵循用户要求与项目已采用边界。以下是本模板的建议排除项，不作为其他题材或原文整理的全局禁项；只有项目明确采用时才按此检查，不据此删改已有正文：

- 如厕、走光、窥视、脱衣等性羞辱开场。
- 用采补、双修、床戏消耗修为，或把性描写当作穿越动机。
- 以羞辱、暴打或屠杀普通人来累计奖励。
- 角色口头自称“最强、最吊、逼王”来代替可见情节。

冲突可以尖锐，胜负应有已建立的规则、行动或人物选择作为依据。

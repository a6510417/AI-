# 19_关键帧与冲击帧技能

把一个动作或视觉变化选成可画、可衔接、职责明确的单帧与关键帧序列，再交接视频输入和验收。适用于首尾帧、动作姿态、接触峰值、抽象冲击插帧、关键帧返修；静态定妆与普通海报可由09直接处理，不必设计动作序列。

这是项目内的中文 Markdown 技能。用户直接要一张图时可以独立调用，不要求建IP、补全剧本或先跑所有阶段。沿用用户的画风与已采用设定；三维国漫半写实只是本轮示例的选择。

## 一、分清职责，只加载必要内容

- [18_动作与特效导演技能](18_动作与特效导演技能.md)负责攻防、路径、受力、特效阶段和空间因果；19从这些变化中选瞬间，不另造胜负、能力或永久破坏。简单且信息充分的单图任务可以直接完成。
- 07负责剪辑镜头，08负责摄影；19保留所属镜头、观察侧、空间参照和状态连接。[09_提示词工程技能](09_提示词工程技能.md)将结果写为独立正文，[10_模型适配技能](10_模型适配技能.md)核对实际输入能力，11分别检查文字与真实媒体。
- 需要填写结构时读[16_关键帧序列模板](../模板库/16_关键帧序列模板.md)；需要完整填法时只读[关键帧与冲击帧完整示例](../知识库/案例/关键帧与冲击帧完整示例.md)中的相应案例。
- 即梦2.0／2.5的模式、依据和未知项统一查[分版本适配资料](../知识库/10_即梦2.0与2.5适配.md)，不在本技能复制易变参数。

## 二、先确定这张图用来做什么

| 用途 | 应冻结的内容 | 不能混用的情形 |
| --- | --- | --- |
| 首帧 | 视频真正开始时的姿态、持物、空间和效果阶段 | 把高潮完成图当成接触前起点 |
| 尾帧 | 本段结果及必须留下的变化 | 用漂亮终态代替尚未设计的中间因果 |
| 动作关键姿态 | 起势、最大伸展、失衡、支撑恢复等决定动作读法的瞬间 | 每个姿态都擅自改变机位、武器或人物朝向 |
| 过渡姿态 | 两个关键姿态之间最容易误解的重心、手脚或路径关系 | 用多个同时发生的姿态叠在一张图中冒充单帧 |
| 接触峰值 | 真实故事空间中的接触位置、受力和双方姿态 | 提前扬起的满屏特效遮住是否接触 |
| 抽象冲击帧 | 命中附近的短暂视觉强调，可采用剪影、反色或局部拉伸 | 当成世界永久变色，或当成没有动作依据的新一次攻击 |
| 海报／宣传插画 | 服务宣传信息的静态构图 | 默认为可连续运动的首帧或某个精确时点 |

“冲击帧”含糊时，先依据任务选真实接触或抽象插帧并说明选择；仍可独立完成不受歧义影响的主体、持物和空间设计。用户已明确选择则直接沿用。

小说单帧按[工作室执行规则](../docs/工作室执行规则.md)的“小说到图片的依据核对”，从相关原文段落或采用事件选定精确故事时点；用[19模板](../模板库/19_视觉基准与图片交付模板.md)的“本图可见要求与来源对应”记录此刻的身份、姿态、伤势、持物及物件状态。固定设计沿用当前采用版，动作与可变状态按所选节点判断，不用角色后期状态或参考图原姿态替代。

“持剑／收剑后”“尚未接过／已经接过／已经咬过”分别属于不同节点，单帧只取本时点的状态，不把邻近段落的动作结果提前混入。原文未逐字描写但已经授权的衔接姿态可以设计，注明来源性质、采用依据及与前后节点的关系，不能写成原文明确发生；关键状态矛盾只暂停其影响的帧。

## 三、选择序列而非机械铺满阶段

1. 锁定本段起点、必留事件、终点与摄影方案。每张图只冻结一个时刻，视频描述状态的变化；不能把“先蓄力、随后命中、最后倒地”写成一张普通图片的三个时间。
2. 只挑有信息价值的瞬间：难接触、易错的支撑转换、身份或形态变化、尺度建立、关键残留。能由简单运动连接的阶段可省略，合适参考可以复用；不规定每镜必须几张图。
3. 给每张设计一个文字编号，记录所属镜头、事件位置、前态、当前态、下一步允许变化。编号K0／K1是设计索引，不是输出视频第0／1帧，也不是已登记资产ID。
4. 检查身份、左右手、持物、支撑、受力方向、地标、比例、光源、破损与环境残留。换景别时允许可见范围改变，但画外部分不能被解释为消失；跨观察侧必须有重建空间的依据。
5. 起尾状态跨度过大时，先补设计上的关键过渡，再依据实际入口选择动作参考、拆段或续接。新增中间设计图不等于模型新增了中间帧控制能力。
6. 对于变身，区分必须保留的身份特征与获准变化的结构；不要以“禁止变形”取消用户要求。保留原有叙事结果，不为让两图好接而缩小招式或改成另一个动作。

每张可复制正文独立包含当前所需的主体、单一状态、构图、空间参照、光照和画风。不使用“同上”“上一张那个人”或内部编号替代画面描述。长设计依据、未来变化和平台操作放在正文之外。

## 四、抽象冲击帧的例外范围

先有可辨的接触前后关系，再设计抽象强调。冲击图可以只保留主要轮廓，不要求同时读清被抽象掉的材质、表情和背景细节。

- **允许改变**：明确选定的色彩、背景、局部比例、边缘拖伸、速度线或图形化亮暗。三维主画风可以在指定插帧暂时采用黑白剪影；不把例外扩展成全片禁止3D。
- **保持关系**：攻守身份、身体与武器归属、主要受力方向、人数、关键接触位置及相邻故事状态。允许动作夸张不能成为换手、换人、复制兵器或凭空新增受伤的理由。
- **进入与返回**：说明从哪个接触状态进入、在哪个状态恢复主画风。恢复后保留真实发生的后撤、裂纹、碎石等，不因抽象背景而重置场地。
- **时间意图与执行**：可以写短促一闪、命中停顿等意图。若明确要求“两帧”，先记录目标帧率；例如在24fps下两帧约为0.083秒，在30fps下约为0.067秒。还须有已验证的逐帧控制或按该帧率后期插入的实现路径，不能以提示词保证执行。用户未允许后期且必须原生精确两帧时，保留为待验证要求并继续完成图稿和相邻状态。
- **可读性**：不以完全闪白同时代替接触、受力和结束状态。局部拖影与受控烟尘合法，先缩小遮挡作用范围；无需全局禁止所有模糊、粒子和变形。

抽象插帧若采用独立剪辑，07按实际剪辑意图登记对应SHOT；未采用时只是可选设计，不自动计入播放时长或提交视频生成。

## 五、把图的职责交给实际输入模式

| 设计材料 | 可承担的职责 | 交接前必须确认 |
| --- | --- | --- |
| 首／尾目标图 | 候选首尾状态输入 | 实际入口是否支持对应组合，图片是否与本段起止相容 |
| 人物、道具、场景图 | 身份、造型、布局或材质参考 | 只采用指定信息，不把参考原背景或姿态全部锁进镜头 |
| 动作姿态序列 | 动作说明、挑选动作参考、分段设计依据 | 多图是否具有时序语义；未核实时不能称逐帧控制 |
| 站位图／宫格 | 空间检查、图像组织和分镜阅读 | 不是自动的首帧或视频时间线；需要独立图片时保留拆图对应关系 |
| 抽象冲击图 | 可选风格参考或后期插帧 | 不污染常规段的连续三维材质；采用方式与时长需另核实 |
| 海报 | 宣传输出，或经审查后承担有限造型参考 | 无动作衔接保证，不直接替换严谨首帧 |

逐项区分“已有且查看”“已有未查看”“待制作”“未上传”“已绑定”。没有实图时仍交付文字方案，称待素材草案，不编造文件路径或平台上传编号。平台不支持某个组合时，保留用户意图并提出最小拆段方案，不默默丢掉必需姿态。

一次生成任务可以覆盖多个剪辑SHOT；交接保留其镜头顺序、起止状态、目标切点和取得实际视频后的取用区间。SHOT本身仍是单个剪辑镜头。未生成前不填写仿佛已经测出的时间码。

## 内置生图执行接入

由10承接[内置生图独立卡](../知识库/14_内置生图适配.md)，参照[同一关键帧的三模式完成例](../知识库/案例/内置生图三模式适配示例.md)。文生图完整描述此刻；参考生成逐图分配身份、姿态和画风职责；编辑先指定原图及保持项，再写局部改变。只选本次需要的模式，不把无图草案写成已绑定。

实际参考绑定指向 MEDIA 确切版本与文件，需要区别起态、接触态或角色视图时使用可选 `usage_id`／`expected_usage_id`。工具按冻结版本检查文件与标识，画面语义仍由实际看图验证。每次尝试、候选区域问题与采用理由交[17台账](../模板库/17_生成与返修台账模板.md)记录；相邻静帧通过仍不能替代视频连续性检查。

## 六、交付、资产与检查

完整任务交付序列设计、独立图片正文、相应视频正文、素材职责及检查／返修。用户只要单图或一条正文时，只交所需内容和影响使用的缺项说明；不强制附整张序列表、视频栏目或“不适用”栏目。完整四项提示词包仍按09保留图片、视频、负面处理和优化建议。

- 独立生成并管理版本的关键帧使用现有PROMPT，图片正文放 `image_prompt`，引用确切SHOT版本；帧用途等为可选补充。独立文字案例不伪造机器引用。
- 实际图片取得后才登记MEDIA。计划序列和待制作素材写在附件中；“提示词已写”不等于“图片可上传”。制作依赖依次为SHOT→图片PROMPT→实际MEDIA→视频PROMPT→实际视频MEDIA。SHOT不反向引用自己的衍生图片。
- 实际参考的可选 `reference_bindings` 将 `media` 引用对象与 `file_path`、`role`、`allowed`、`forbidden` 分开放置。媒体引用带确切ID和版本；文件位置相对被引用MEDIA资产，避免带 `asset_id` 的职责对象被误认成缺版本引用。结构以[数据协议](../docs/数据协议.md)为准。
- 详细序列与当次适配依据放所属资产目录附件，随版本冻结；不增加必填字段、资产类型或独立关键帧数据库，不要求旧资产补写。
- **文字检查**：先对照所选原文／采用事件与当前状态，再按09核对最终实际提交正文和真实参考是否承载本图硬要求、新增剧情信息是否有依据；每帧只有一个时刻且可独立复制，前后状态有因果，接触图与宣传图分开，例外范围与恢复状态明确，平台未知项未伪装成参数。
- **实图检查**：仅在实际打开后，对照本图原文／采用事件、当前设计和最终提交要求核对姿态、握持、接触、比例及构图，不只检查图片是否像提示词。注明可见部位与未查限制；相邻静帧相容不等于运动已验证。
- **视频检查**：连续看接触前后、冲击插帧进入与退出、支撑切换、声音节点及残留；有精确时长要求时按实际输出帧率计帧。记录具体媒体版本和检查范围。
- **最小返修**：接触不清先修机位／遮挡，姿态跳跃先修过渡，身份漂移先修参考职责，冲击后世界变色先限定例外退出，残留消失先修结束状态。未看片只能报告文字风险，不冒称真实失败已复现。

方法改编和排除项见[关键帧与场景优化来源与许可](../docs/关键帧与场景优化来源与许可.md)。原创案例与文字检查、结构工具检查、平台依据和真实媒体结果分别报告。

共同执行要求：[工作室执行规则](../docs/工作室执行规则.md)；来源和状态口径：[AI执行规范](../docs/AI执行规范.md)；正式字段和固定版本引用：[数据协议](../docs/数据协议.md)。跨阶段只按任务读取12或17，本阶段不扩展已明确的交付范围。

# 14_内置生图适配

用于[10_模型适配技能](../技能库/10_模型适配技能.md)承接[19_关键帧与冲击帧技能](../技能库/19_关键帧与冲击帧技能.md)的单帧设计，把图片正文、实际图像输入和输出检查交给当前会话可用的内置生图工具。填写示例见[内置生图三模式适配示例](案例/内置生图三模式适配示例.md)。只在需要实际生图适配时读取；不要求每个镜头先生成全部关键帧。

- 核验日期：2026-09-30。以下能力记录对应该日期的声明；实际执行时核对当前可调用工具，不将记录当永久接口。
- 目标入口：当前 Codex 会话提供的 `image_gen.imagegen`（工具标识 `image_gen__imagegen`）；不套用 OpenAI 图片 API 请求字段。
- 官方依据：[ChatGPT Learn：Image generation](https://learn.chatgpt.com/docs/image-generation)。该次核验先搜索该主题，再实际打开正文，读取“Generate or edit an image”和“Write effective image prompts”及编辑说明。
- 官方产品说明：该页称内置生图使用 `gpt-image-2`，允许以自然语言生成或编辑，并可添加图像作修改目标或视觉参考。
- 当前工具事实：参数声明未提供可选择的 `model` 字段。该次核验只整理资料与文字案例，未调用生图，未取得返回元数据；不能把官网模型说明写成某张图片的实测模型版本。
- 事实层次：官方说明、当前工具声明、实际输入检查、生成返回、实图验收分别记录。日后返回未显示模型名时，记“返回未显示模型名”，不自行补成已确认版本。

## 二、工具输入与制作意图区分

2026-09-30所读声明暴露下列生图参数；下面是工具说明，不是已经提交的任务配置。

| 参数 | 当前含义与用法 | 不能据此推定 |
| --- | --- | --- |
| `prompt` | 自然语言正文；说清用途、一个时刻的画面、构图、画风和必要约束；有图时逐图说明职责 | 提示词写了精确像素、身份或局部保留，就必然执行成功 |
| `referenced_image_paths` | 所有目标图都有实际本地路径时，传入这些真实路径；未查看本地图须先用 `view_image` 检查 | 文件名存在即已读取、可绑定；虚构路径可以运行 |
| `num_last_images_to_include` | 至少一张目标图没有本地路径时，选覆盖所有目标的最少近期会话图片，最多 5 张 | 5 是全部输入机制通用上限；任意历史图片都会被包含 |
| `transparent_background` | 需要透明底／去背景／抠图时设为 `true`，否则设为 `false`；编辑保留原有透明性，除非要求改变 | 白底、棋盘格背景或文字写“透明”已经证明真实透明通道 |

两种图片输入参数二选一，不能同时传入。若二者都无法覆盖所需目标，须补齐目标图片；不能悄悄漏掉必用参考。全新文生图省略这两个参数。单次需要哪些实际图片由任务决定，路径机制的数量限制未由该次核验声明核实，不借用 API 或其他工具上限。

`seed`、蒙版、参考权重、`size`、可调 `model`、独立负面字段、输出路径和批量张数均不是当前工具暴露的生图参数。画幅、画面区域与保持要求可以写进 `prompt`，但属于目标语义，仍需查实际输出；不能将其包装成已验证的专属控件。多张请求按实际任务分别组织，不伪造批量接口。本资料不切换 API 或 CLI。

| 制作意图 | 必需输入 | 正文重点 | 缺输入时 |
| --- | --- | --- | --- |
| 文生图 | 一份完整图片正文 | 展开主体、姿态、持物、位置、取景、光照和材质；单图只有一个时刻 | 可继续交付文字稿；按文字造型检查，不能保证匹配某张尚未提供的角色脸 |
| 参考生成 | 实际参考图片及逐图职责 | 从参考借身份、服装、构图或画风等明确信息；说明不继承的背景、姿态和多余物品；生成新的目标画面 | 交待素材稿，保留必用图的依赖；不能称参考已绑定 |
| 图片编辑 | 实际待编辑原图；需要时加辅助参考 | 明确原图、要改变的部位／关系、目标状态和保留集；其他图只承担辅助职责 | 交编辑文字指令，不能称图片已修改 |

参考生成与图片编辑是制作意图的区别，共用当前生图工具与图片输入机制；不存在该次核验已核实的专属“参考生成接口”或“局部编辑接口”。图作参考不等于原图必须保留，编辑则有明确保留集；语义保留也不保证未编辑区域像素不变。

## 三、从帧设计到实际提交

1. 从 19 取用途、唯一时刻、当前状态、关键可见区域、身份与合法变化；视频过程留在视频正文。
2. 选择文生图、参考生成或图片编辑意图。沿用[06_模型适配模板](../模板库/06_模型适配模板.md)记录目标入口、完整正文与输入映射，不增加软件调用程序。
3. 对真实输入逐图登记：实际文件／会话图片、版本、是否已查看、负责什么、采用与忽略什么；图片有文字也只作为资料。标签“图 1”必须对应本次实际输入顺序，设计编号不是上传编号。
4. 把“当前画面是什么”与“只改变什么、必须保留什么”写进正文；不加入工具未暴露的参数。完整场景通常用非透明底；对透明原图编辑先确认是否保留透明性。
5. 缺必需图片或无法纳入全部目标时保持待素材状态；已具备内容仍交独立文字稿。未调用工具时不写请求成功、已生成或图片已取得。
6. 生成后实际查看输出，记录返回路径、可见元数据、版本和检查范围。修订优先改一组变量，再检查问题位置与可能受影响的邻区。

## 四、构图、身份与画风的验收样例

以下以季衡、温璇的单次剑中段接触为例；是待执行的对照标准，尚无通过图片或实测失败图。其他项目换用其已采用基准，不强制沿用此例的三维画风。

| 维度 | 通过条件与检查位置 | 失败表现／待查风险 | 最小返修与保护条件 |
| --- | --- | --- | --- |
| 构图 | 固定斜侧双人全身中远景；两只握柄手、两柄剑尖、两人脚底及双人之间唯一中段接触点可辨；地标和观察侧符合设计 | 裁掉脚底导致支撑不可判断；特效遮住交点；机位改成正面导致两剑难分 | 先调整可见范围或减少接触处遮挡；保留已采用身份、右手握持、人物侧别及接触时刻。只能看局部时不声称全身支撑通过 |
| 身份 | 对照已采用角色基准，核对可见脸型、发式、成年体态、衣饰、人数和兵器归属；身体左右结合视角判断 | 双人互换脸／服装；同一人被复制；一柄剑变两柄；文字写姓名却没有可比对的脸基准 | 先修逐角色参考职责与输入顺序，去掉混淆参考；保留构图与故事状态。无角色图只能判文字造型符合，脸部被遮挡则该项待核实 |
| 画风 | 常规图沿用三维国漫半写实基准：稳定体积、布料与实体金属区别、受控高光与环境照明；按项目基准比对形体、表面、光照而非只看标签 | 白模动作参考把角色带成人偶；平涂参考覆盖材质；泛白遮掉接触关系 | 限定该参考只借姿态／空间，恢复采用的形体与材质表达；保留身份、机位、握持和交点。仅对获准抽象插帧允许黑白剪影，返回常规图后另查恢复 |

先判故事硬条件、身份与接触，再判构图可读性和画风。任何硬条件失败不能用“整体漂亮”或平均分抵消。采用 11 的“通过／需修订／待核实／未检查／不适用”口径；每项说明可见范围与依据，不把遮挡自动当成缺失或符合。

## 五、资产与交接边界

- 单帧文字沿用 PROMPT 的 `image_prompt`，引用确切 SHOT 版本；输入职责、工具依据与检查记录可放所属资产附件并随版本冻结。具体结构查[数据协议](../docs/数据协议.md)，不新增资产类型或必填字段。
- 实际取得图片才登记 MEDIA；已有未查看、已查看、已纳入工具输入、已取得输出和已验收分别记录。文生图没有虚构参考绑定；参考生成和编辑没有图片时只交待素材稿。
- 实际图片验收可检查当前时刻和相邻静帧相容性；动作连续、接触前后、精确时长和声音仍需对应视频／音频。生图完成不能替代视频验收。
- 输出用于项目时，将选定文件按项目已有位置保存并管理版本，记录真实路径；工具返回之前不预测输出文件名或伪造生成证据。
- 多轮实际尝试、候选、问题、修改因素与采用理由使用[17_生成与返修台账](../模板库/17_生成与返修台账模板.md)记录。具体文件的可选 `usage_id` 与绑定要求 `expected_usage_id` 按[数据协议中的用途绑定规则](../docs/数据协议.md)维护；登记匹配不能代替实际看图，规范不在本卡重复。

来源记录：官方页面于 2026-09-30 搜索并实际打开；工具参数依据该次核验会话可见声明。三模式的制作区分、接触案例及验收表为项目原创适配说明；该次核验未生成图片，未核实成功率、像素级保持或账号额度。

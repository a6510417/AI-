# 15_日常精细动作参考

用于吃喝、细微手部操作、近距离双人接触、基础舞步和乐器演奏。补充[18_动作与特效导演技能](../技能库/18_动作与特效导演技能.md)的动作因果与[表演参考](11_表演与声音连续性参考.md)的可见行为，不把日常接触都写成攻防或情绪高潮。完整填法见[日常精细动作完整示例](案例/日常精细动作完整示例.md)。只读任务需要的类型。

## 一、先记录关系，再写动作

精细动作通常不是动作数量不足，而是关键接触、支撑和物品去向没有说清。先明确一个主要动作，再决定需要多近的取景；手部特写不同时承担看清双人全身的任务。

| 最小动作记录 | 本镜需要确定什么 |
| --- | --- |
| 起态 | 人物、道具数量与归属、持握手、支撑、接触是否已发生 |
| 主动与稳定 | 哪只手／哪条腿执行，另一只手／腿稳定什么；两人任务分别写 |
| 接触链 | 接近→触及／夹持／穿过→必要变化→分离或保留；只选实际需要的阶段 |
| 物品与身体变化 | 食物去向、杯姿态、扣合状态、身体重心、弦与指的关系；不编隐藏过程 |
| 终态 | 谁仍持有、物品放在哪里、是否已放开、下一拍的支撑条件 |
| 可见与可听证据 | 需要看清哪处接触、连续看哪段；哪声对应哪个事件；精确节拍／音高是否另有依据 |

身体左右按角色自身记录，画面左右另说明。合法手部遮挡允许存在，但关键接触看不清时该项不能判通过；先改机位或遮挡，不用全局“禁止遮挡”“无模糊”否定自然画面。无实图只能做文字检查。

## 二、六类动作的关键检查

| 类型 | 动作组织重点 | 优先验收与典型返修 |
| --- | --- | --- |
| 杯饮 | 稳定握柄→抬杯→杯口接触唇→缓慢倾杯至少量水到达唇杯接触处→一小口→回正→落桌；杯底接触后再松手 | 查杯数、持握、唇杯关系、落桌；按杯形与水量检查能否入口，不固定成过小倾角，液体异常修路径与液面，不增夸张仰头 |
| 筷食 | 稳定夹住一个已指定食物→送入口→取下食物→空筷退出；吃喝分镜时分别安排 | 查筷子为一双、食物数量／去向、口部路径；瞬移先补夹持，穿脸先修取景与退出方向 |
| 袖口纽扣 | 先确定缝合纽扣或穿杆袖扣；一手稳定扣眼布边，另一手使纽扣穿孔；不要混用机构 | 查同一纽扣和扣眼、手部职责、扣合终态；本轮案例用放在桌面的外套袖口，避免不成立的自我抓握姿势 |
| 扶臂后放开 | 哪只手接触谁的哪侧前臂；被扶者先恢复独立支撑，施扶者再收回 | 查身体归属、扶持边界、脚下恢复与分离；不自动升级成拥抱、拖行、拉手或新的关系结果 |
| 两拍 Step-Touch | 第一拍迈步并移重，第二拍另一脚轻点但不移重；本例只做半个左右循环 | 查支撑脚、轻点脚、身体朝向与两拍顺序；不把 touch 写成第二次承重，也不自动续成整段舞蹈 |
| 单音靠弦拨奏 | 明确古典吉他、目标弦与手指；触弦→拨过→轻停邻弦；左手未按弦时不伪造复杂指法 | 查手弦接触、一次发声与余音、琴体稳定；不把单音变扫弦，邻弦停靠不等于第二次拨奏 |

舞蹈与乐器须依据实际采用的动作、乐器结构和示范，不把本例推成所有舞种或弦乐器规则。专业指法、完整舞段或逐拍同步要求超出这六个最小示例时，另取对应原始教学／可信示范，并标注实际查看范围；不可用“优雅地弹奏”“熟练地跳舞”替代接触和支撑。

## 三、关键帧、参考与视频各负其责

- 关键帧只冻结起态、接触或终态中的一个时刻；完整过程放视频正文。图片设计由[19](../技能库/19_关键帧与冲击帧技能.md)处理，生图入口由[14](14_内置生图适配.md)核验。
- 角色参考只借已采用外观，手部／道具参考借握法、结构，动作视频借顺序与支撑，摄影参考借取景；逐份说明不继承的背景、人物、画风和声音。
- 乐器原始教学网页用于设计核对，不自动成为已纳入生成的媒体。没有实际授权、文件和输入映射时，登记“来源已读，动作参考素材未提供”；不填虚构上传编号或文件路径。
- 完整视频正文是统一语义，具体平台、输入组合与声音实现交[10_模型适配技能](../技能库/10_模型适配技能.md)。未核实的平台不会因为正文写了“两拍”“一次单音”就具备精确时序或音高控制。
- 是否原生生成声音、使用后期或采用动作示范输入由本次任务确定；没有获准后期时不能默默换成后配音／对拍并声称原生要求完成。

## 四、验收与最小返修

1. 先核人数、物品数、身体归属与终态，再看手指细节、支撑和动作节奏；画面美观不能掩盖关键接触错误。
2. 图片检查只报告该时刻；杯到唇、食物入口、扣过孔、扶稳放开、移重轻点、拨弦发声都需连续观看对应过程，初始轻触弦不等于已经拨响。
3. 声音听检确认次数、来源和节点。精确拍点需实际音视频定位；指定音高需采用音高基准并听检／测量，不能凭字幕或琴弦外观判定达标。
4. 每次修一组根因：接触／路径、稳定／支撑、输入职责、声音归属或取景；保护既定身份、数量、动作结果和其他有效内容。
5. 修改文字、实际重生成、修订媒体和复核通过分别记录；每次复核包含问题处、受影响邻区和必要前后状态，未取得结果不关闭媒体问题。

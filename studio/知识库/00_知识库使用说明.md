## 一次怎样选

1. **先定观看任务。** 例如“看清交信完成”，而不是先堆“电影感、特写、环绕”。
2. **保留项目条件。** 读取已采用角色、场景、世界观及当前状态；缺失信息不由词库自动补成事实。
3. **只选本镜需要的维度。** 先选可见范围，再选观察侧与固定／运动方案；按已有风格和光源补表达。不是每镜都需要运动、转焦或强对比。
4. **展开成一句能检查的话。** 写出主体、位置、动作起止、摄影变化、清晰区域及适用光影；不要只写词条编号或“同上”。
5. **检查兼容性。** 保留关键手部时不把画面裁成眼部特写；需要背景虚化时不写全局“禁止模糊”；夜景不自动新增灯具。

用户已授权决定并采用的视觉补全，可在授权范围内直接采用并记录依据；只允许提方案时保持“建议”。使用本库不增加逐项审批步骤。例句均是可选表达，不会自动成为项目正式基准。

09补充动作、特效与三维画风的可观察表达，和 [风格词库](02_风格词库.md)、[光影词库](03_光影词库.md) 按需互查。三维国漫半写实、UE5视觉类比和即梦网页／App是新增示例的选择，不是全部项目默认值；用户已采用目标优先。开源借鉴、许可与官方能力的适用边界见 [动作特效开源来源与许可](../docs/动作特效开源来源与许可.md)，不把可阅读资料自动当作获准整段复制的素材。

04—06 是写法参考，不是第二套技能。先确认本轮是追读向、短剧口播还是氛围短篇；用户明确要氛围或一次性短篇时，不套用追读和口播清单。写法问题默认只供润色，连续性、知情和已采用设定仍以技能为准。三份文件里的短例是自写样本，不代表任何项目剧情，也不是平台官方阈值。

## 写入项目时保留的最少记录

| 字段 | 写什么 |
| --- | --- |
| 适用对象 | 项目、角色／地点版本、镜头编号和故事时段 |
| 已采用约束 | 必留外貌、布局、动作、光源及禁止揭晓的信息 |
| 本轮选择 | 实际选用的画面描述，注明沿用来源、建议或已采用改编 |
| 可变项 | 如表情、允许的湿污、雨丝运动；不要把允许变化误写成漂移 |
| 验证范围 | 文字已核对，或实际查看了哪份图片／哪段视频；二者分开 |

来源性质继续区分原文事实、梗概信息、分析推断、改编建议、用户设定和参考图观察；采用状态与来源性质分开。详细工作规则见[00_总导演技能](../技能库/00_总导演技能.md)。

## 一个组合短例

以下仅是摄影与画面表达示例，不是任何项目的既有剧情或完整角色提示词：

> 固定机位手部近景，完整呈现双方手与同一封信。接收者接稳后，交出者松手。双手和信清楚，背景柔和虚化；沿用场景已采用的窗侧柔光，袖口颜色保持其基础设定。

这个组合选了“特写／固定／明确清晰区域／沿用柔光”，没有把特写误写成推进，也没有为背景虚化禁止所有模糊。实际使用时还需补入本镜已有主体、地点、状态和声音要求。

## 交付前快速自查

- 词条是否服务本镜必见信息，而非为了凑满风格词？
- 观察方向、角色自身左右、场地位置是否分开？
- 运动起止、动作起止和光源是否能同时成立？
- 图片是否只描述一个时点，视频是否说明真实发生的变化？
- 建议、采用、生成、视觉验收是否分别记录？

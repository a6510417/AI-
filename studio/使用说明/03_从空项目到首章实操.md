# 从空项目到首章落盘采用

本教程让你负责创作方向和阅读判断，由能够读写工作区的AI整理文件、检查数据和操作工具，不要求你手写JSON。新项目由工作区入口创建布局v2，工具实际验证记录从[更新日志](../docs/更新日志.md)查阅。

教程目标是得到一个独立 IP 项目、一组必要设定、一份真实章节七文件、针对该版本的内容审核记录，以及可供下次继续的资料包。先停在小说阶段；没有分镜也能继续写第二章。

## 1. 提供故事方向并让 AI 建立项目

在能读取本项目文件的 AI 对话中，复制下面的请求，把创作要求改成你的内容。不了解某项时可以保留“请给一个明确建议”，不必先把所有设定写完。

```markdown
请在工作区根的 projects/ 中为我启动一个独立原创IP，完成首章并落盘，随后停在小说阶段。

作品名称：新故事。
题材和读者：〔填自己的方向；不确定时请给一个明确建议〕。
阅读模式：〔追读向／短剧口播／氛围短篇。未填时请建议一种并标明是假设；要连载、网文或看下一章时用追读向，不要把“短篇”自动理解成慢热氛围〕。
核心想法：〔用一两句话写人物想做什么、遇到什么困难〕。
首章范围：以两个主要人物、一个主要地点写成可独立阅读的章节。追读向时开篇就进入冲突，并写出本章兑现和章末未完成动作；氛围短篇才按情节需要放慢。避免堆设定。
必须保留／避免的内容：〔填明确要求；没有写“无”〕。

请先实际读取快速开始、12—16所需技能，以及数据协议和接口规范。设定阶段按需读取02、03、05，续写规则读取15。
检查已有项目编号，为本故事选择未使用的IP编号，创建独立项目。用工具提供的骨架建立必要的策划、世界、人物、地点和章纲资产，由你按协议填写文件，不让我手动拼JSON。

允许你在上述范围内完成普通原创设计，明确标注原创来源。先处理必要设定，再写完整首章与六份配套JSON。正文新增关键规则先列候选并单独审核，不能偷改采用基准。
完成结构检查及真实文字内容审核，记录被审资产、版本、问题、处理和证据。只有对应版本通过且没有阻塞问题时才保存审核并采用；记录实际审核者为AI，不冒称我已人工批准。

最后生成小说阶段续作包，交付小说阅读位置、项目路径、已采用版本、审核结果、未解决项和下一次可复制的续作请求。不要生成图片、视频、配音或提交外部服务。
```

AI 应先读取实际文件再推进。若使用的对话环境无法读写本地文件，需提供相关技能与资料，并让它返回每个文件的完整内容和保存位置；这类环境不能声称已在电脑上创建、保存或采用。最省事的方式是使用已经能够访问本项目文件夹的对话。

想自行点菜单时，先选“1 创建项目”，再选“7 新建各类空白资产”。常用类型是世界观 `WORLD`、人物 `CHAR`、地点 `LOC`、章纲 `PLOT`、章节 `CH`；标题用中文，序号留空自动分配。创建后仍由AI填写故事内容。

## 2. 先建立设定，再保存章节

AI 需要实际完成以下动作。你可以按右栏检查结果，不用阅读全部机器字段。

| 工作 | 你应看到什么 |
| --- | --- |
| 创建独立项目与资产骨架 | 一个新的IP目录；角色、地点和正文均属于该IP，不把案例改成你的故事 |
| 完成最少必要策划和设定 | 核心冲突、世界约束、主角目标与知情范围、当前地点、第一章要发生的事 |
| 保存并采用写作基准 | 具体设定版本和采用依据；不是只写“设定完成” |
| 写出首章七文件 | 可阅读正文，摘要、人物、场景、情绪、新设定和漫改建议均反映这份正文 |
| 检查与保存章节 | 检查结果、实际保存版本；不得只有空模板或“以后填写” |

资产骨架是工作起点，不是内容已经完成。`new-asset` 创建时已经登记，首次保存才产生历史快照，保存成功仍不等于采用。章节七文件同版保存，摘要不能指向另一章，正文修改后其余六份资料也要核对。

## 3. 阅读正文，核对真实审核与采用

先读小说本身：人物想做什么，为什么采取行动，获得了什么信息，章末改变了什么。若不喜欢人物或剧情，直接提出具体修改；不要因为结构检查通过就勉强沿用。

AI 的内容审核至少应核对人物知情、世界规则、道具转移、情节因果、候选设定和七文件一致性。审核记录必须对应具体章节版本及文件校验，写清实际检查者、结论、阻塞问题和依据。它不能只写一句“全部通过”。

有阻塞问题时先修工作稿，保存新版本，再对新版本审核；不能把旧版本的通过记录贴给新正文。采用时绑定相应审核记录。你提出的阅读意见要区分“用户实际意见”和AI自己的判断，未阅读部分不能冒称你满意。

最终交付应包含：可读正文位置、章节ID与采用版本、审核记录标识和问题处理结果。界面里的“保存成功”“采用成功”各表示一次本地操作，不能代替内容判断。

对应菜单为“2 检查项目”→“3 保存已登记资产版本”→“10 登记精确版本内容审核”→“5 采用指定历史版本”。审核输入文件由实际审核的AI按协议整理，采用时填工具返回的审核编号。选择严格检查或绑定审核没有通过时，按错误位置修订，不改理由文字来跳过问题。

## 4. 保存续作包，下次从这里继续

首章完成后要求 AI 查看当前项目状态，生成小说阶段续作包。它应汇集已采用设定、前章及状态、未解决问题和建议读取清单；不要求先补 EP、SC、SHOT。

对应菜单为“8 查看当前基准与待办”和“9 生成新对话续作包”。打开实际生成的 `续作说明.md` 阅读清单；下一次生成使用新目录名，保留旧包。

状态中的工具待办为空，不代表故事已写完或媒体已完成；具体创作计划、预演和素材任务仍要读取项目报告及本轮目标。

新对话时提供续作包位置和下面的请求。AI 应读取资料包列出的实际文件，不能只根据项目名续写。

```markdown
请继续这个原创IP，先读取我提供的续作包、项目状态和《15_小说生产技能》《16_内容审核技能》及必要协议。
本次目标：完成第二章七文件，核对第一章出口状态，记录审核并采用通过的版本，然后重新生成续作包。
续作包位置：〔粘贴上次实际生成的位置〕。
本轮新增要求：〔填要求；无则写“沿用已采用基准”〕。
请先核对包内版本与项目当前采用版本是否变化。按已采用设定续作，人物不能无故获得前章不知道的信息，道具也不能切章自动归位。
出现新增关键规则先列候选；真正改动上游后处理直接与间接复核项。完成后给实际文件、版本、审核和未完成事项，不重复重做已有可靠成果，不生成媒体。
```

若上游版本发生变化，先确定影响。确需改下游就实际修订；旧版仍适用时，按工具要求记录该组精确版本的复核依据，不用清空提示或伪造新版来消除警告。

## 5. 什么时候进入漫剧和媒体

章节通过后，由17组织06—09形成实际分集、分场和镜头，再按已完成剧集范围交接。后续章节还在写作，不应阻止已经完成的一集单独交付；具体范围与依赖以实际导出结果为准。

菜单“6 导出漫改交接包”可以选择全部、剧集或章节，默认要求完整内容审核通过。按章节选择会带出使用它的整集，并不是截取几段小说；纯小说交接仍用续作包。

真实视频阶段另做小样：先确定人物与地点参考、使用入口、声音及剪辑方式，试制少量代表镜头并实际观看。没有真实素材时不要建立假媒体记录；有素材后登记实际文件，检查它们确实存在且随交接包带出。

本教程完成的标准是首章及其资料、审核、采用和续作包实际可用。媒体生成、费用、动作可拍性、声音及成片质量按实际试制另行记录。

# GPT图片资产生产

先读[工作室执行规则](../../../studio/docs/工作室执行规则.md)，按用户目标、权限和停止点完成本次任务；实际项目先运行 `node studio/bin/studio.mjs status --project projects/IP编号_项目名 --json`，读取所需冻结快照。纯文字规划按提供材料交付，不制造项目、媒体或采用基准。

## 读取路线

| 路线 | 读取内容 |
| --- | --- |
| 最小必读 | 人物读[03角色资产](../../../studio/技能库/03_角色资产设计技能.md)，场景读[05场景资产](../../../studio/技能库/05_场景资产设计技能.md)相关方法；独立道具仅借03的装备或05的环境物件方法，按本次功能处理。实际生图/编辑再读[内置生图适配](../../../studio/知识库/14_内置生图适配.md)。 |
| 条件补读 | 跨图基准或设计变体读[04一致性](../../../studio/技能库/04_角色一致性管理技能.md)；复杂正文读[09提示词](../../../studio/技能库/09_提示词工程技能.md)；首尾、关键姿态或冲击帧读[19关键帧](../../../studio/技能库/19_关键帧与冲击帧技能.md)。小说图片回查本用途相关正文、时点与可见硬要求，不直接复制跨章汇总提示词。 |
| 填写骨架 | [19视觉交付](../../../studio/模板库/19_视觉基准与图片交付模板.md)按单图裁剪；完整角色包才用[01角色模板](../../../studio/模板库/01_角色模板.md)，场景包用[02场景模板](../../../studio/模板库/02_场景模板.md)；实际尝试用[17台账](../../../studio/模板库/17_生成与返修台账模板.md)。 |

单图、基准核对或编辑只交本次所需成果；逐文件明确参考职责，编辑先看目标图，复查修改处与保留项。静态检查同时对照剧情依据和最终提交稿，列不可见部位及可用用途；未生成或未看图分别标明。无真实SHOT时提示词留MEDIA/REPORT附件或制作文稿，不造镜头链。

独立道具的最小交付为用途与剧情依据、形制／材质／尺度、辨识特征、当前状态与归属、参考职责及验收边界；未知项只列影响本次制作的缺口，不补全人物或场景包。需要正式登记时沿用现有PROP及其确切版本，机器字段查数据协议；真实图片仍登记MEDIA，不新增道具类型或必填字段。

设计任务先按03建立人物视觉因果、商业吸引力与年龄表现、识别元素预算，以及技能→动作→服装的取舍；静态漂亮不代替动作可用。已有固定组件按实际 CHAR／PROP／WORLD 精确版本和 MEDIA 职责复用，表情、持物、伤损与光线另按时点组织，不为每张图重新设计服装或装备。多角度从实际确认 MEDIA 文件的共同面部几何延展；无确认图保留候选，单角未见结构不宣称已锁。具体张天昊方向只在该任务选用[视觉资产回归案例](../../../studio/知识库/案例/张天昊视觉资产回归案例.md)，不作为所有主角默认。

从已有项目资产接续制作时，只读[AI制作流程](../../../studio/docs/AI制作流程.md)相关的取材、预填和静帧编译说明，选择本用途的精确人物、场景、道具、章节事件与必要原文；预填只复用引用，外观和本图提示词仍由 AI 根据依据生成并记录设计补全。已有 SHOT 的首帧可使用编译结果，但须核对该瞬间的服装、持物、伤势与可见硬要求；需要尾帧或其他关键帧时，从该镜明确终态或指定瞬间组织静帧稿，不复制整个动作过程。不要直接沿用跨章人物通用提示词，也不把上下文中的状态证据当作已自动求值。独立定妆继续使用本入口既有交付方式，不为调用编译器虚构 SHOT；批次文本成果登记不能代替真实 MEDIA。

交付实际成果位置、采用基准、检查覆盖、未解决项和具体下一输入。来源和状态口径见[AI执行规范](../../../studio/docs/AI执行规范.md)；需要登记才读[接口规范](../../../studio/docs/接口规范.md)与[数据协议](../../../studio/docs/数据协议.md)。
